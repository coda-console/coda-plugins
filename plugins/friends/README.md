# 好友

管理本机的 Accord 身份与熟人好友通道（`coda/accord@1`），并提供业务无关的好友网关（`friends/social@1`）。

- **本机身份**：身份卡显示本机的展示名、确定性几何纹头像、公钥短码（点按复制），下方状态条给出已互认好友数（有待互认、冲突时提示）与身份、证书状态。没有建身份时显示「未建身份」并提示前往客户端「设置 › 身份」创建。
- **公钥派生的昵称与头像**：本机和好友都没有可编辑的昵称、照片、Emoji 或主题色，统一由 Accord 公钥推出。展示名是 `昵称 #尾号`：昵称按 coda#3040 的算法取公钥 256 位，从最高位起每 7 位一组（至多 36 组），`0–77` 为字母、`78–87` 为数字、`88–127` 为结束符（已有不足 2 位时跳过，够 2 位就结束，读完仍不足 2 位则没有昵称）；尾号是公钥按大端整数转成十进制（补零到 78 位）后的末 4 位，同昵称且末 4 位相撞的公钥从右往左逐位加位直到区分（如 `xs #04084`、`xs #14084`）。撞号一起比的是当前页面（跨电脑时是视图里所有电脑）上的全部本人公钥与好友公钥；网关 `friends` 操作的 `title` 则由本机身份与全部好友一起比。解不出昵称时退回公钥短码（`ed25519:` 之后前 8 位），还没有公钥的待互认好友用节点名。头像是由公钥确定性生成的 5×5 几何纹，灰色，换设备也一样；没有合法公钥时取名字首字。这些算法不在插件里：页面用 WebView 标准库 `coda-view://lib/v1/accord.js`，Node 侧（网关、代理记录）用 `@coda-console/protocol/accord`，两者是同一份实现，测试用协议包的测试向量对齐。
- **添加好友**：点身份卡上的「添加好友」，粘贴对方给的邀请（JSON、`coda-friend://` 链接或多行 `key=value`），接受后自动尝试互认。邀请也可以在同一个弹层里生成，见下文「生成与接受邀请」。
- **同身份通道合并**：同一台电脑上，指向同一个完整公钥（`author`）的多条通道（如 `node:` + `link:`、两条 `link:`，或对方多台设备共用个人根身份）合并成一张好友卡片：状态里有冲突就算冲突（不隐藏密钥冲突），否则有已互认的算已互认，其余为待互认；多条连接时副标题写「N 条连接」，已互认的好友名下还有待互认通道时再注明「（M 待互认）」。没有公钥的待互认通道不与任何条目合并。详情里公钥与「共享」归整个好友，「连接」一节逐条列出各通道（通道键、机器、范围有差别时一并写出），每条各自有状态、重新互认和二次确认的移除，移除一条后弹层留在其余连接上；只有一条连接时详情保持原样。好友数、状态条与网关 `friends/social@1` 的 `friendCount`、`friends` 都按合并后的好友统计。
- **好友列表**：实时跟随好友表变化，宽屏双列。点好友打开详情：昵称、几何纹头像、完整公钥（可复制）、节点名、连接状态、「共享」（见下文「把远程执行授给好友」）、重新互认、二次确认后移除。
- **社交网关 `friends/social@1`**：业务无关，别的插件（在 `optionalUses` 里声明）经它读好友与好友分享的记录、向好友发布与撤回记录，不必各自处理没有身份、证书过期和重试。

## 几台电脑

页面不自己选电脑：App 的全局视图里有哪几台，页面就读哪几台，没有机器标签。

- **本机身份按公钥显示**：按各台 Accord 的 `spec.author` 分组，同一身份只显示一张身份卡，视图里有不同身份的电脑时每个身份一张。
- **好友按电脑分节**：每台一节，顺序同视图，节标题是电脑名；节里是这台自己的好友通道（好友关系按机器上的通道登记，在 A 上加的好友 B 上不会自动出现），状态条（好友数、证书状态、待互认与冲突）和「添加好友」也在这一节。接受邀请与随后的互认、好友详情里的重新互认、移除，都发给这一节、这一行所在的电脑。没有好友的电脑也占一节；同一个好友在两台上都加了，就在两节里各出现一次，不跨电脑合并（合并只在同一台电脑内按完整公钥进行）。读不到的电脑（`unreachable`）节里写明原因，不出「添加好友」。
- **只有一台时**页面不出现节标题，状态条与「添加好友」仍在身份卡上。
- **推荐用法**：好友只在一台电脑上加。好友关系登记在那台电脑上，别的电脑不会自动出现这个好友。邀请里的入网码只能用一次，不必在每台上重复加。
- **要共享别的电脑**：不必在那台上再加一次好友。加了好友的这台作网关，能把同一空间里别的电脑的远程执行逐台授给好友（见下一节「经网关授出别的机器」）。
- **几台电脑绑定同一个身份、又在同一个空间里时**，其他电脑发布的记录由 Coda 在这几台之间同步，好友从加了他的那台读取（见 Coda 仓库 `docs/peers.md`）。这是 Coda 基座的行为，本插件不另外保证，也不检查同步是否已经完成。

## 把远程执行授给好友

好友之间可以把一台机器上的 `remote-exec`（协议 `remote-exec/machine@1`）授给对方：对方的 Agent 经本机的代理记录，在你的机器上执行命令。授出的可以是加好友的这台自己，也可以是同一空间里别的机器（这台作网关）。`remote-exec` 本身不感知好友，签名、验签与转发都在本插件里（「仅限目录」的授权只是每次调用时带上 `remote-exec` 自己的 `restrict` 参数，见「授权的范围」）；没装 `remote-exec` 的机器照常使用好友功能（清单里是可选实现与可选依赖）。

### 用法

- **授予**：在好友详情的「共享」一节，「我授给 TA」点「授予…」，选一台机器：列表里先是这台自己，再是同一空间里打开了远程执行的别的机器，都按机器名列出，一次授一台。选定后出范围表单，见下面的「在页面上选范围、看范围、改范围」。前提是已互认（已绑定好友通道），并且被授出的那台在 `remote-exec` 里打开了「允许本空间的机器在这台上执行」。
- **范围**：授予时选「整台机器」（默认）或「仅限目录」，授出后可以改，页面上的用法见下面的「在页面上选范围、看范围、改范围」，范围本身的含义见「授权的范围」。
- **撤销**：授权那一行的菜单选「撤销」。撤销以本机为准，立即生效：还没启动的调用不再启动，已经在跑的发取消，授权先显示「撤销中」，取消在后面跟上，不弹确认。
- **用好友授给我的**：「TA 授给我」里的每一条是一条代理记录，名字见下面的「代理记录的名字」，同步在你的空间里。会话里像用本机的远程执行一样，对这条记录调用 `exec`；你空间里的别的机器也能用，签名和收回答由持有这条记录的那台机器做。
- **看别人做了什么**：持有方在「共享」里能看到最近的操作记录（谁、哪条授权、命令摘要与结局，仅限目录的授权还有当时的范围）。

### 在页面上选范围、看范围、改范围

**授予时选范围**：「授予…」里点一台机器，出现范围表单（上面是这台机器的名字、系统和用户）：

- **整台机器**（默认选中）：等同于登录这台机器上的这个账号。点「授予」，与以前一样先在列表里出现「授予中」的一行。
- **仅限目录**：下面出目录列表。每行一个目标机上的绝对路径加「读写」或「只读」；「添加目录」加一行、「删除」去掉一行，路径手输（页面不浏览目标机的文件系统）。至少一行、至少一行「读写」、至多 50 行，路径要以 `/` 开头。不合规时「授予」按钮不可用，列表下面写明缺什么（哪一行没填、不是绝对路径、没有读写行、超过 50 行），不会发出请求。
- **只有 macOS 的机器能选「仅限目录」**：目标机系统不是 macOS 时这个选项是灰的，旁边写明「第一期只支持 macOS 的机器」。这只是按机器记录里的系统给的提示，授予时持有方到目标机探测的结果才算数（见「授权的范围」）。
- 点「换一台机器」回到列表重选，范围与填过的目录都重置。

**授「仅限目录」要等探测**：点「授予」后，持有方先到目标机上探测一次，要几秒，最长约 30 秒。这期间按钮是「正在探测…」，表单上的内容都不能动、也不能关，只会发出一次请求。成功了表单关掉、授权出现在「我授给 TA」里；失败了表单不关、填的内容都留着，改一下可以直接再点「授予」。提示由错误码决定，持有方的原话作补充放在提示下面，目录类的错误会指出是哪一行（并把那一行的输入框标红）：

| 提示 | 意思与怎么办 |
| --- | --- |
| 这台机器不能用「仅限目录」 | `sandbox_unsupported`：目标机不是 macOS，或没有 `/usr/bin/sandbox-exec`。这台只能授整台机器 |
| 这台机器上的「远程执行」版本太旧 | `restrict_unsupported`：到那台机器上把 `remote-exec` 升到 0.2.0 及以上 |
| 第 N 行……不存在／不是目录 | `restrict_dir_not_found`、`restrict_dir_not_a_directory`：那一行的路径在目标机上没有、或不是目录，改路径 |
| 第 N 行与第 M 行……重叠 | `restrict_overlap`：允许目录之间不能互相包含或重复，请去掉其中一条（表单提交前就地检查字面部分，经符号链接、大小写的以目标机为准） |
| 第 N 行……受保护的位置 | `restrict_protected`：目录不能包含、也不能落在 Coda 的状态目录或 `~/.ssh` 里面（整个家目录因为包含 `~/.ssh` 也不行），请选与它们不重叠的目录 |
| 目标机上的沙箱起不来 | `sandbox_failed`：目标机上沙箱没跑通，原话在提示下面 |
| 目标机现在离线／读不到目标机／记录不在了／已经不是…… | `target_offline`、`target_unreachable`、`target_missing`、`target_changed`：目标机的状态不对，等它回来、让它重新打开远程执行，或关掉表单重选 |
| 目标机 30 秒内没有回应 | `timeout`：确认目标机在线、远程执行已打开，再试一次 |
| 范围太大 | `restrict_too_large`：目录太多或路径太长，签不出授权记录，减少或缩短 |
| 已经授给 TA 一条范围不同的授权 | `already_granted`：同一位好友对同一台机器只有一条有效授权，到那一行的菜单选「修改范围…」 |
| 目标机上的远程执行没打开 | `disabled`：让那台机器在 `remote-exec` 里打开开关 |
| 没有收到目标机的回应 | 页面等了 45 秒还没有回复（不是目标机的错误码）：表单关掉，那一行显示「待确认」（授予是新出现的一行，改范围是原授权行上），页面每隔几秒读一遍列表核对；之后才到的回复照常处理（成功就并入，明确失败写在那一行）。核对读到想要的结果就落定；连续几遍都没有，授予的一行变成「未授予」可重试，改范围的一行写明「没有确认范围改成功」、仍是原来的范围，可以再改 |

这些失败都没有建或改任何东西（没有回应那一条除外，以后面的核对为准）。授「整台机器」不探测，也不会出现这些提示。

**看范围**：

- 「我授给 TA」的每一行，名字下面是范围：「整台机器」，或「仅限目录 · 第一条目录（读写／只读）等 N 个」（只有一条时不写「等 N 个」）。点开能看到全部目录和各自的「读写」「只读」，长路径折行显示、不会撑破一行。
- 「TA 授给我」的每一条同样写「整台机器」或目录摘要，点开看全部目录。这只是展示：放行与限制只在对方的网关与目标机上。
- 「最近的操作」里，仅限目录的调用有「仅限目录 · N 个」的标记，点开是那次调用当时的范围；整台机器的调用没有标记。

**改范围**：「我授给 TA」里仍可用的授权，行尾菜单选「修改范围…」，打开同一张表单，机器固定不能换，范围预填现在的。可以改目录，也可以在两种范围之间切（切到「整台机器」不探测）。点「保存范围」，同样要等探测，失败的提示同上。已撤销、已失效（目标不在了、本机或好友的身份变了）、正在撤销的授权，菜单里没有这一项。改完对之后的调用生效，已经在跑的不动。

### 授权的范围

一条授权有一个范围，是这条授权自己的属性（同一位好友对同一台机器仍只有一条有效授权）：

- **整台机器**：好友的命令不受限，与以前一样，也是没有范围字段的旧授权的含义，不需要迁移。
- **仅限目录**：`restrict: { dirs: [{ path, access }] }`，`path` 是目标机上的绝对路径（至多 1024 字节），`access` 是 `rw`（可读写）或 `ro`（只读）；1 到 50 行，至少一行 `rw`（与 `remote-exec` 一致）。好友的每条命令都在目标机的 macOS 沙箱里执行，只能读写这些目录（外加系统运行所需的只读路径和本次调用专用的临时目录，例外见 `remote-exec` README「受限执行」）。

**怎么授、怎么改**（页面上的用法见上一节；在会话或脚本里也可以经 `coda self` 调同名的操作，页面用的是同名的消息）：

```
coda self grants.grant '{"friend":"ed25519:…","target":{"kind":"remote-exec/machine@1","id":"…"},"restrict":{"dirs":[{"path":"/Users/me/work","access":"rw"}]}}'
coda self grants.restrict '{"grant":"<授权号>","restrict":{"dirs":[…]}}'     # restrict 不给（或 null）是改回整台机器
```

- **授予时先到目标机探测**：授「仅限目录」之前，网关向目标机发一次带这份 `restrict` 的 `exec`（命令 `true`，不给 `cwd`，没有副作用，目标机的操作记录里会有一行），目标机认了才建授权；不通过就当场失败、什么也不建、不签发，错误码与原因如下。授「整台机器」不探测。改成「仅限目录」同样先探测，不通过就不改。

  | 错误码 | 原因 |
  | --- | --- |
  | `sandbox_unsupported` | 目标机不是 macOS，或没有可执行的 `/usr/bin/sandbox-exec` |
  | `restrict_unsupported` | 目标机上的远程执行版本太旧（0.2.0 之前），按 schema 拒绝了 `restrict` 字段 |
  | `restrict_dir_not_found`、`restrict_dir_not_a_directory` | 某个目录在目标机上不存在、不是目录（消息里有路径） |
  | `restrict_protected` | 某个目录包含或落在目标机受保护的位置里（Coda 状态根、`~/.ssh`） |
  | `restrict_overlap` | 允许目录互相重叠（相同、一条在另一条里面，字面或真实路径上）；目标机为了不让受限命令经可写目录里的链接改道、也不让「只读」子目录实际可写而拒绝，消息里有冲突的两条 |
  | `sandbox_failed` | 沙箱起不来，或探测命令没跑成 |
  | `target_offline` | 目标机离线（已记成离线的不发探测；探测时连不上也是它） |
  | `timeout` 及目标机的其他码 | 30 秒内目标机没有回应，或它的远程执行没打开（`disabled`）等，原样带回 |
  | `restrict_too_large` | 范围写进授权记录后超过签发的 64 KiB 上限（路径里的引号、反斜杠、控制字符转义后更长），签不出去；在落盘与探测之前就拒绝，请减少目录或缩短路径 |
  | `invalid_input` | `restrict` 形状不合格，没发探测 |

  探测是权威：授予页上目标记录的 `os` 以 `Darwin` 开头只是「可能支持」的提示（`grants.targets` 每行的 `restrictHint`）。
- **已有授权**：授予先看有没有已有的有效授权，再决定要不要探测：范围相同原样给回那一条，范围不同报 `already_granted`（消息里带授权号），改范围走 `grants.restrict`；这两种都不探测，目标离线、探测会失败时也一样。只有确实要新建时才探测。
- **改范围**：落盘就对之后的调用生效：准入时与提交给目标机之前读的都是新范围，提交那一刻的范围记进在途项，重启后接手的也按它；已经在跑的调用不动。改完用同一个授权号重新签发授权记录（版本递增），好友看到新范围；目标暂时读不到（别台被移出空间）期间改的，待重新签发的状态保留，目标带着相同的 spec 回来后签出新范围。
- **每次调用带什么**：「仅限目录」的授权，网关每次都把授权行里的 `restrict` 写进交给目标机的 `exec` 输入（直接授出本机、与经网关转给空间里别的机器两条路径一样）；「整台机器」的不写。好友请求里的 `restrict` 与任何未知字段在重建输入时丢掉，不透传，也去不掉授权行里的。好友没给 `cwd` 就不填，目标机用第一条 `rw` 目录；给了就须在允许的目录里（否则目标机以 `cwd_not_allowed` 拒绝）。目标机返回的沙箱类错误码与效果原样带回好友。
- **页面消息**：`grants.grant`、`grants.restrict` 经视图消息失败时，回复是 `{ type: 'reply', rid, ok: false, error, effects, code }`，`code` 是上表的稳定错误码（还有 `already_granted`、`not_found`、`invalid_state` 等），页面不必解析中文消息；成功的回复没有 `code`。
- **好友这一侧**：「TA 授给我」的每一条（`proxies.list`）带 `restrict`（仅限目录的才有，没有是整台机器），只用来展示，放行与限制只在网关与目标机。代理记录 `spec` 的形状不变（它登记在 `remote-exec/machine@1` 下，加字段旧节点会丢掉整条记录），仅限目录的授权，`spec.cwd`（默认目录）是第一条 `rw` 目录。代理记录的 `exec` 不收 `restrict`，当场以 `invalid_input` 拒绝，免得调用方以为自己收紧了、实际没有。

**能挡什么、挡不住什么**：用的就是 `remote-exec` 的受限执行，挡得住与挡不住的、macOS 沙箱的例外、错误码与已知限制见它的 README「受限执行」：这些目录之外的文件内容、`~/.ssh`、Coda 的整个状态根读写不到（系统运行所需的 `/usr`、`/bin`、`/sbin`、`/private/etc` 等只读路径，以及本次调用专用的临时目录，命令仍可使用），包括本插件的 `rpc/grants.json`（已有测试里真跑沙箱确认）；不禁网、不限 CPU 与内存，目录是否存在与元信息不保证不可见。同一系统用户下，不受限的调用（含「整台机器」的授权）仍够得着这些，所以「仅限目录」只约束带限制的那条命令。

**目标机要求**：macOS，有 `/usr/bin/sandbox-exec`，远程执行 0.2.0 及以上。要不要升目标机的远程执行，授予时的探测会说。

**新旧版本互通**（授权的范围随好友插件 0.10.0）：

- 「整台机器」的授权签出的记录与以前逐字节一样（`v: 1`），旧版好友照常能用。
- 「仅限目录」的授权记录是 `v: 2`，多一项 `restrict`。旧版好友的校验严格要求 `v` 是 1、不许多出字段，**收下前就拒掉**：新授予的在旧版好友那边不出现代理记录；已登记的授权被改成仅限目录后，旧版那边的代理记录留着但标为不可用（「好友的授权记录不在了，或和这位好友的通道已断开……」，调用当场失败、没发出任何请求），不会显示成一条可用的整台机器授权。要让旧版好友用上，请他升级。
- 旧版网关（持有方）读到新版写的 `grants.json`：只要表里有一行带范围，文件的 `v` 就是 2，旧版把它当损坏、停止准入（`grants.list` 的 `corrupt` 是 `grants.json`），绝不会把仅限目录的授权当整台机器放行；表里没有带范围的行时文件还是 `v: 1`，旧版照常读。降级后要用，先把仅限目录的授权改回整台机器（表里没有带范围的行了，文件回到 `v: 1`）。操作记录里带 `restrict` 的行，旧版读不了（该月的记录显示损坏，记不下新的），只影响记录。
- 范围在好友那边只是展示：好友篡改或伪造它没有用，放行与限制只在网关与目标机。

### 代理记录的名字

名字固定为 `<机器名>@<公钥昵称>#<尾号>`（coda#3040），只由好友的公钥算出，与好友页上的展示名同一套算法（协议包 `@coda-console/protocol/accord`）。

- **公钥**：好友表里这位好友存下的作者：绑了个人身份的是个人钥匙，没绑的是机器钥匙；证书过期时仍是存下的那把，名字不跟着变。
- **昵称**：与基座的 `AccordNickname` 同一套：32 字节公钥从最高位起每 7 位一组，至多 36 组；0–77 是字母（对 26 取余），78–87 是数字，88–127 是结束（不足 2 位时跳过）。解不出昵称的用公钥前 8 位十六进制。
- **尾号**：完整尾号是公钥按大端无符号整数写成的十进制，补零到 78 位，记在代理记录的 `tail` 标签里。名字里默认写最后 4 位；本机同一 `<机器名>@<昵称>` 的代理记录最后 4 位也相同时，这几条都写到能互相区分的最短位数（协议包的 `disambiguateTails`）。
- **会话里的 `target`**：可以写 `机器名@昵称`（不撞名时）或 `机器名@昵称#尾号`（尾号从最后一位往前数的任意位数），这要求基座含 coda#3040；更早的基座只认完整名字或记录地址。
- **机器名**：是持有方自己报的，要能放进标题：含控制字符（C0、DEL、C1）、换行、双向控制符，或首尾有空白的，调用方不登记这条授权（不替换、不裁剪：改完的名字可能与别的记录相同）；授予时被授出的那台机器的名字不合这条，授予当场失败。`@`、`#`、中间的空格、非 ASCII 文字照旧可以。
- **名字的范围**：名字只在当下在场的记录里判唯一。另一位好友可以专门挖一把昵称相同、末 4 位也相同的钥匙（昵称越短越容易），再授出一台同名机器：两条都在时会被要求带更长的尾号；前一条不在时，后一条就是唯一匹配。基座（含 coda#3040）的保护是：会话开场表里列出过的名字，在这个会话里始终指开场时那条记录，那条没了就报不可用。脚本、Skill、定时任务这类跨会话的引用写记录地址（`coda://…/<UUID>`），地址不会换主人。

### 授权的含义

持有方始终以**机器**出现：授权是那台机器上的本机的事，授权记录与回答都用它的机器钥匙签，与它有没有绑个人身份、证书是否过期无关。

- **授给个人身份的好友**：就是授给这个人名下的机器，以及这些机器上被好友插件放行的会话。
- **授给机器身份的好友**（对方没绑个人身份，只装了后端）：只授给对方那一台机器。
- 授权记下授予那一刻核验到的调用方作者。调用方后来绑了个人身份、解绑或换了根，旧授权与代理记录立即停用，要重新授予；持有方这一侧只有机器钥匙变了才停用：绑定、解绑个人身份或换根都不影响它授出去的授权。另外，目标记录删掉了，授权也随之结束（`target_missing`），之后重建同 id 的记录也不会恢复，要重新授予。

### 经网关授出别的机器

加了好友的这台（网关 A）可以把同一空间里另一台 B 的远程执行授给好友。好友只和 A 互认，请求先到 A，A 核对授权后用 Coda 的跨机调用去调 B；B 不用和好友互认，也不用装好友插件。

- **能授出什么**：只有机器自己的 `remote-exec` 记录（本机的，或空间里别的机器自己的），一台一台选；A 能调用的机器不会自动对好友开放。别的好友分享来的代理记录不能再转授，页面不列，授予也会被拒。A 要装着 `remote-exec`，才看得到别的机器的这类记录。
- **每次核对**：授权记下目标是哪台机器的哪条记录。每次准入和提交前，A 重新核对好友身份、授权没撤、目标仍是那台机器上 `remote-exec` 的那条记录，对不上就拒绝。好友只能用被授予的那条，只开放 `exec`。
- **B 离线**：授权保留，B 回来后接着能用。空间约 3 分钟没听到 B 才把它记成离线：
  - 已记成离线的：「我授给 TA」里显示「目标离线」，请求在交给 B 之前就被拒，好友当场收到 `target_offline`、效果 none。
  - 还没记成离线的那几分钟：命令照常交出、排在 A 这边等 B。等到「命令时限 + 60 秒」还没结局，A 放弃这次调用，好友收到 `timeout`、效果未知。放弃时 Coda 用取消顶替还没送到 B 的调用，B 回来先收到取消，不会再执行这条命令。
- **B 被移出空间**：A 读不到 B 的记录，显示「读不到目标」，好友当场收到 `target_unreachable`、效果 none，授权保留；B 回到空间后接着能用。
- **B 的记录确实没了**（B 关了远程执行、卸了插件）：B 仍在空间里而记录已不在，授权随之结束（`target_missing`），之后要重新授予。
- **撤销**：同本机的授权，A 撤销后立即拒绝新请求，正在 B 上跑的调用经 Coda 的取消结束。
- **好友那一侧**：B 显示为一台机器，名字是 B 的机器名（`B的机器名@昵称#尾号`）；授权与回答仍由 A 的机器钥匙签，好友插件 0.8.0 起就能用，不用升级。
- **B 的机主看得到什么**：B 上的远程执行只看到来自 A 的调用，看不出是替哪位好友发的；哪位好友、什么命令记在 A 的「最近的操作」里。

### 生成与接受邀请

- **生成**：在「添加好友」弹层的上半点「生成邀请」（需在 Coda 客户端里打开好友页）。邀请带入网码和**一次性口令** `bindingToken`，24 小时内有效，只能用一次；它是凭据，只显示这一次，关掉弹层就清掉。
- **接受**：弹层下半粘贴对方的邀请，接受后自动互认。没有口令的邀请会被拒绝，请对方重新生成。
- 邀请的字段、口令的校验与互认的细节见 Coda 仓库的 `docs/peers.md`，这里不再另列。

### 已知限制

- **同一系统用户**：被执行的命令和后端是同一个系统用户。本机的授权文件、操作记录（好友插件记的和 `remote-exec` 自己的）挡不住同一用户下的别的程序，`0600` 也挡不住；它们防得住误操作，防不住有意抹痕迹。
- **命令全文**：`remote-exec` 自己的记录存命令全文；本插件的操作记录默认只存前 80 字摘要与 sha256，不存 `cwd`、`stdin`（留 90 天）。
- **清理会延后**：
  - 持有方的回答：到终态后满 24 小时才撤回；持有方用机器钥匙，不受证书影响。
  - 调用方的请求：拿到结局后撤回，拿不到就等过期后撤回；离线或证书不可用时推迟到恢复以后。但如果过了期限再满 24 小时仍签不了名，本地的发出项会被清掉，之后不再补撤。
- **只转发 `exec`**：`pull`、`push` 在第一个字节之前报不支持，请改用 `exec` 分段读写。
- **撤销会取消在跑的调用**：取消后拿不到确定结局的，记为中断、效果未知；命令可能仍在对方机器上执行，重跑之前先检查。
- **按目录停用好友插件不会停止共享**：插件模块属于机器，在目录里停用好友插件后，对方的调用照常执行。要停止共享，请撤销授权或卸载插件。
- **移除好友只在本机断交**：只在执行移除的这一台删掉绑定、终止授权和目录同步。空间里别的机器若也和这位好友互认着，要分别移除。如果这位好友是你发邀请加进来的，对方的节点仍留在你的网络里：到得了各台后端的好友入口，读得到后端公开的绑定信息，但调不了命令、读不到记录正文；用过的邀请绑不回来，拿到你另一份有效的邀请则可以。节点的去留：
  - 移除后由有网络凭据的客户端在好友页收回；收不了的显示在「网络节点待移除」，可以重试。
  - Headscale 上认得出节点是哪份邀请带进来的；Tailscale 和认不出的，要逐个确认后再删。
- **好友换身份的后果**：好友原来以机器身份互认，之后绑上个人身份，好友关系保留（coda#3041）。
  - 你授给它的授权钉在原作者上，会按「被授权的好友换了作者」失效，要重新授一次。
  - 它授给你的不受影响；好友从机器身份绑上个人身份后，TA 授来的机器在本机的名字会变（主干和尾号都跟着公钥换）。
- **机器钥匙没有时限，也不能原地轮换**：持有方带个人身份的，换了机器要重新互认并重新授予；没有个人身份的，机器丢了只能移除这条好友通道。
- **调用方的证书**：调用方绑了个人身份就要靠客户端按时续签证书，过期后调用当场失败。
- **时钟**：两边时钟差超过 2 分钟，或本机时钟大幅回拨，都会拒绝或暂停准入。
- **断线后变慢**：连接断过一次后，回答可能晚 12 到 45 秒；75 秒内没有「运行中」回执，调用按 `peer_offline`、效果未知失败。
- **同根的别台机器也能用**：几台电脑绑定同一个身份、又在同一个空间里时，好友授给你的代理，别台机器也看得到、调得动，不必在每台上各自登记。调用经持有这条代理记录的那台转发，那台要在线。能看到是因为空间会同步代理记录，与是否同根无关。
- **请求被拒时**：授权在、请求方就是被授权人且仍是已绑定的好友时，持有方签回失败的结局，写明原因（如 `revoked`、`target_unreachable`、`target_offline`），效果 none，好友当场知道命令没有执行；这样的回答照常占每分钟的名额。别的请求（没有这条授权、不是好友、超了名额）持有方只记账、不回答，调用方 75 秒内收不到回执，按 `peer_offline`、效果未知失败。
- 配额：每个好友至多 8 个在途、4 个同时执行、每分钟 30 个新请求；全机 32、8、120。

## 社交网关

签名写入与记录查询全部透传 `coda/accord@1`，网关自己没有第二份目录库。本机网关记录（`friends/social@1`，key `local`）的 `status` 给出作者、证书状态（`no_identity` / `needs_cert` / `active`）、好友数、待发数与暂停的 kind。

| 操作 | 作用 |
| --- | --- |
| `friends`（读） | 互认的好友（`includePending` 带上待互认与冲突的），只来自 Accord 的好友表：`{ selfAuthor, certState, friends }`，每行的 `title` 是公钥派生的展示名，不读名片记录；指向同一公钥的多条通道合并成一行，顶层 `node`、`peerNode`、`scope` 取代表通道，`channels` 列出各条通道 |
| `records`（读） | 按 `kind`、`author`、`id`、`cursor` 读好友分享的记录，不读 `binding` 与 `friends/rpc-` 前缀 |
| `publish` | 发布 `{ kind, id, body, audience? }`；同作者同内容不重发，换作者重发 |
| `retract` | 撤回一条，或省略 `id` 撤回本机在这个 `kind` 下的全部（含队列里还没发出去的） |
| `outbox`（读） | 待发与已同步条目的状态，从不给出 `body` |

- `publish`、`retract` 拒绝保留类型 `binding`、`profile`、`friends`、`friends/card`、`coda/profile`、`coda/friends` 与整个 `friends/rpc-` 前缀；`kind` 须是 Accord 的格式，`id` 至多 200 个字符、256 字节，`body` 是对象且 JSON 至多 64 KiB，`audience` 每项是 `public` 或 `ed25519:` 加 64 位十六进制，至多 500 项。
- 没有身份、证书过期（或发布遇到 `invalid_state`）、`kind` 被暂停、发布失败时，待发的 `body` 暂存在本机 `outbox.json`；同步成功就释放 `body`，只留去重用的 `lastAuthor`、`lastSyncedHash`、`lastSyncedAt`；撤回完成就删掉条目。证书恢复后自动补发、补撤；待撤的条目记着排队时的作者（`targetAuthor`），换了作者不会替新作者撤，没有身份时的撤回只清本机未发出的待发，不排待撤。意图先落盘再签名，签名成功立即落盘确认；`outbox.json`、`policy.json` 读不出来（不是缺失或损坏）就报错，不当空表。
- 旧版留在 `outbox.json` 里的保留类型条目（如已下线的名片 `friends/card`、升级前入队的 `friends/rpc-*`）读表时直接丢掉，随启动或下一次冲洗落盘清理，不补发、也不挡着别的待发条目。插件不会去撤回 Accord 里历史上已发布的旧名片记录。
- 暂停与恢复某个 `kind` 的外发：`coda self policy.setKind '{"kind":"…","paused":true}'`，`coda self policy.get` 读现状（`policy.json`）；暂停只拦发布，不拦撤回。

## 已下线的功能

名片编辑（昵称、照片、Emoji、字标、主题色、裁剪上传）、本机备注（`notes.json`、`coda self notes.*`）、`set-card`、私信 `send-dm`、动态 `post-feed` 与 `dm`、`feed` 两条帧流都已移除。插件本地写 `outbox.json`、`policy.json` 与「共享」用的 `rpc/` 目录（授权、发出项、操作记录）；旧版留下的 `notes.json` 不再被读取。

## 权限与数据边界

- `friends/social@1` 的权限组：`read` 管 `friends`、`records`；`publish` 管 `publish`、`retract`、`outbox`。
- `uses`：`coda/accord@1` 的 `read`（读好友表）、`publish`（网关代别的插件发布）、`manage`（接受邀请、互认、移除）；`coda/machine@1` 的 `read`（别台的目标读不到时，看那台还在不在空间里）。`optionalUses`：`remote-exec/machine@1` 的 `use`（转给本机的远程执行，没装就没有这部分）。
- 保留种类 `friends/rpc-grant`、`friends/rpc-call`、`friends/rpc-answer`：只有本插件的内部入口能签发与读取，通用网关的发布、撤回、`records`、`outbox` 都不给出。
- 入网码（`authKey`）是凭据：只在提交时用一次，提交后立即清空输入框，不写入任何文件、日志或页面状态。
- 节点名等外来数据只当文本渲染（`textContent`），不当指令或 HTML。
- 好友页的 Accord 读写在页面交互时发起；模块只在 `activate` 时监听本机 Accord 记录（证书、好友表），用来刷新网关记录、证书恢复后冲洗待发队列。
- 待发的 `body` 只在本机 `outbox.json`，不经别处。
