# 好友

管理本机的 Accord 身份、个人名片与熟人好友通道（`coda/accord@1`）。

- **我的名片**：名片卡显示昵称、头像、主题色与本机公钥短码（点按复制），下方状态条给出已互认好友数（有待互认、冲突时提示）与身份、证书状态。
- **编辑名片**：头像可选照片、几何纹（按公钥生成）、Emoji 或字标（昵称首字，写进 `emoji`）。照片从本机选图，在弹层里拖动、缩放裁成 512×512，优先编 WebP（不支持时用 JPEG），上传到 `coda-view://blob/content` 后把内容指针写进名片的 `avatar`；只改昵称、颜色不重新上传，换成非照片头像时写 `avatar: null` 清除。名片以公开的 `profile` / `self` 记录发布；本机绑定了代签证书、`profile` 被拒（`forbidden`）时改发可代签的社交名片 `friends/card` / `self`。
- **添加好友**：点名片上的「添加好友」，粘贴对方给的邀请（JSON、`coda-friend://` 链接或多行 `key=value`），接受后自动尝试互认。邀请也可以在同一个弹层里生成，见下文「生成与接受邀请」。
- **好友列表**：实时跟随好友表变化，宽屏双列；显示好友的照片头像（读不出时退回 Emoji、几何纹或首字，点「刷新」重试）。点好友打开详情：完整公钥、节点名、本机备注、重新互认、二次确认后移除。
- **社交网关 `friends/social@1`**：业务无关，别的插件（在 `optionalUses` 里声明）经它读好友与好友分享的记录、向好友发布与撤回记录、发私信与动态、实时跟随私信与动态，不必各自处理没有身份、证书过期和重试。

## 几台电脑

页面不自己选电脑：App 的全局视图里有哪几台，页面就读哪几台，没有机器标签。

- **我的名片按身份显示**：按各台 Accord 的 `spec.author` 分组，同一身份只显示一张名片，视图里有不同身份的电脑时每个身份一张。同一身份的几台读到的名片不一样（同步有先后）时取记录版本高的那份，不逐字段比对。改名片只发给这个身份里视图顺序第一台能签名（证书可用）的电脑，页面只确认这一台写入成功，头像也上传到这一台；其他电脑要等同步后才显示新名片（同步见下面的「推荐用法」）。不会向几台都发，两台同时改的冲突不处理。
- **好友按电脑分节**：每台一节，顺序同视图，节标题是电脑名；节里是这台自己的好友通道（好友关系按机器上的通道登记，在 A 上加的好友 B 上不会自动出现），状态条（好友数、证书状态、待互认与冲突）和「添加好友」也在这一节。接受邀请与随后的互认、好友详情里的备注、重新互认、移除，都发给这一节、这一行所在的电脑。没有好友的电脑也占一节；同一个好友在两台上都加了，就在两节里各出现一次，不合并。读不到的电脑（`unreachable`）节里写明原因，不出「添加好友」。
- **只有一台时**页面不出现节标题，状态条与「添加好友」仍在名片上。
- **推荐用法**：好友只在一台电脑上加。好友关系登记在那台电脑上，别的电脑不会自动出现这个好友。邀请里的入网码只能用一次，不必在每台上重复加。
- **几台电脑绑定同一个身份、又在同一个空间里时**，其他电脑发布的记录由 Coda 在这几台之间同步，好友从加了他的那台读取（见 Coda 仓库 `docs/peers.md`）。这是 Coda 基座的行为，本插件不另外保证，也不检查同步是否已经完成。

## 把远程执行授给好友

好友之间可以把一台机器上的 `remote-exec`（协议 `remote-exec/machine@1`）授给对方：对方的 Agent 经本机的代理记录，在你的机器上执行命令。`remote-exec` 本身不感知好友，签名、验签与转发都在本插件里；没装 `remote-exec` 的机器照常使用好友功能（清单里是可选实现与可选依赖）。

### 用法

- **授予**：在好友详情的「共享」一节，「我授给 TA」点「授予…」，选本机的一条远程执行记录。前提是已互认（已绑定好友通道），并且在 `remote-exec` 里打开了「允许本空间的机器在这台上执行」。
- **撤销**：授权那一行的菜单选「撤销」。撤销以本机为准，立即生效：还没启动的调用不再启动，已经在跑的发取消，授权先显示「撤销中」，取消在后面跟上，不弹确认。
- **用好友授给我的**：「TA 授给我」里的每一条是一条代理记录，名字见下面的「代理记录的名字」，同步在你的空间里。会话里像用本机的远程执行一样，对这条记录调用 `exec`；你空间里的别的机器也能用，签名和收回答由持有这条记录的那台机器做。
- **看别人做了什么**：持有方在「共享」里能看到最近的操作记录（谁、哪条授权、命令摘要与结局）。

### 代理记录的名字

名字固定为 `<机器名>@<公钥昵称>#<尾号>`（coda#3040），只由好友的公钥算出，好友改名片、你改备注都不会变，别的好友也没法用同名名片顶替。本机备注和好友的名片名只在好友页上给人看，不参与命名与寻址。

- **公钥**：好友表里这位好友存下的作者：绑了个人身份的是个人钥匙，没绑的是机器钥匙；证书过期时仍是存下的那把，名字不跟着变。
- **昵称**：与基座的 `AccordNickname` 同一套：32 字节公钥从最高位起每 7 位一组，至多 36 组；0–77 是字母（对 26 取余），78–87 是数字，88–127 是结束（不足 2 位时跳过）。解不出昵称的用公钥前 8 位十六进制。
- **尾号**：完整尾号是公钥按大端无符号整数写成的十进制，补零到 78 位，记在代理记录的 `tail` 标签里。名字里默认写最后 4 位；本机同一 `<机器名>@<昵称>` 的代理记录最后 4 位也相同时，这几条都写到能互相区分的最短位数。
- **会话里的 `target`**：可以写 `机器名@昵称`（不撞名时）或 `机器名@昵称#尾号`（尾号从最后一位往前数的任意位数），这要求基座含 coda#3040；更早的基座只认完整名字或记录地址。
- **机器名**：是持有方自己报的，要能放进标题：含控制字符（C0、DEL、C1）、换行、双向控制符，或首尾有空白的，调用方不登记这条授权（不替换、不裁剪：改完的名字可能与别的记录相同）；持有方授予时本机那台机器的名字不合这条，授予当场失败。`@`、`#`、中间的空格、非 ASCII 文字照旧可以。
- **名字的范围**：名字只在当下在场的记录里判唯一。另一位好友可以专门挖一把昵称相同、末 4 位也相同的钥匙（昵称越短越容易），再授出一台同名机器：两条都在时会被要求带更长的尾号；前一条不在时，后一条就是唯一匹配。基座（含 coda#3040）的保护是：会话开场表里列出过的名字，在这个会话里始终指开场时那条记录，那条没了就报不可用。脚本、Skill、定时任务这类跨会话的引用写记录地址（`coda://…/<UUID>`），地址不会换主人。

### 授权的含义

持有方始终以**机器**出现：授权是那台机器上的本机的事，授权记录与回答都用它的机器钥匙签，与它有没有绑个人身份、证书是否过期无关。

- **授给个人身份的好友**：就是授给这个人名下的机器，以及这些机器上被好友插件放行的会话。
- **授给机器身份的好友**（对方没绑个人身份，只装了后端）：只授给对方那一台机器。
- 授权记下授予那一刻核验到的调用方作者。调用方后来绑了个人身份、解绑或换了根，旧授权与代理记录立即停用，要重新授予；持有方这一侧只有机器钥匙变了才停用：绑定、解绑个人身份或换根都不影响它授出去的授权。另外，目标记录删掉了，授权也随之结束（`target_missing`），之后重建同 id 的记录也不会恢复，要重新授予。

### 生成与接受邀请

- **生成**：在「添加好友」弹层的上半点「生成邀请」（需在 Coda 客户端里打开好友页）。邀请带入网码和**一次性口令** `bindingToken`，24 小时内有效，只能用一次；它是凭据，只显示这一次，关掉弹层就清掉。
- **接受**：弹层下半粘贴对方的邀请，接受后自动互认。没有口令的邀请会被拒绝，请对方重新生成。
- 邀请的字段、口令的校验与互认的细节见 Coda 仓库的 `docs/peers.md`，这里不再另列。

### 已知限制

- **同一系统用户**：被执行的命令和后端是同一个系统用户。本机的授权文件、操作记录（好友插件记的和 `remote-exec` 自己的）挡不住同一用户下的别的程序，`0600` 也挡不住；它们防得住误操作，防不住有意抹痕迹。
- **命令全文**：`remote-exec` 自己的记录存命令全文；本插件的操作记录默认只存前 80 字摘要与 sha256，不存 `cwd`、`stdin`（留 90 天）。
- **清理会延后**：
  - 持有方的回答：到终态后满 24 小时才撤回；持有方用机器钥匙，不受证书影响。
  - 调用方的请求：拿到结局后撤回，拿不到就等过期后撤回；离线或证书不可用时推迟到恢复以后。但如果过了期限再满 24 小时仍签不了名，本地的发出项会被清掉，之后不再补撤。
- **只转发 `exec`**：`pull`、`push` 在第一个字节之前报不支持，请改用 `exec` 分段读写。
- **撤销会取消在跑的调用**：取消后拿不到确定结局的，记为中断、效果未知；命令可能仍在对方机器上执行，重跑之前先检查。
- **按目录停用好友插件不会停止共享**：插件模块属于机器，在目录里停用好友插件后，对方的调用照常执行。要停止共享，请撤销授权或卸载插件。
- **移除好友只在本机断交**：删掉绑定、终止授权和目录同步。如果这位好友是你发邀请加进来的，他的节点仍留在你的网络里，到得了各台后端的好友入口，但调不了命令、读不到发给别人的记录，也不能自己重新绑上。要彻底收回，到控制服务器（Tailscale 或 Headscale）上删掉那个节点。
- **好友换身份的后果**：好友原来以机器身份互认，之后绑上个人身份，好友关系保留（coda#3041）。
  - 你授给它的授权钉在原作者上，会按「被授权的好友换了作者」失效，要重新授一次。
  - 它授给你的不受影响，只是代理的名字会跟着新作者变。
- **机器钥匙没有时限，也不能原地轮换**：持有方带个人身份的，换了机器要重新互认并重新授予；没有个人身份的，机器丢了只能移除这条好友通道。
- **调用方的证书**：调用方绑了个人身份就要靠客户端按时续签证书，过期后调用当场失败。
- **时钟**：两边时钟差超过 2 分钟，或本机时钟大幅回拨，都会拒绝或暂停准入。
- **断线后变慢**：连接断过一次后，回答可能晚 12 到 45 秒；75 秒内没有「运行中」回执，调用按 `peer_offline`、效果未知失败。
- **同根同步（待验收）**：几台电脑绑定同一个身份、又在同一个空间里时，好友的记录会不会同步到我的别台机器，留给 G4 沙箱实测，结论回填于此。
- 配额：每个好友至多 8 个在途、4 个同时执行、每分钟 30 个新请求；全机 32、8、120。超限的请求持有方只记账、不回答，调用方 75 秒内收不到回执，按 `peer_offline`、效果未知失败。

## 社交网关

签名写入与记录查询全部透传 `coda/accord@1`，网关自己没有第二份目录库。本机网关记录（`friends/social@1`，key `local`）的 `status` 给出作者、证书状态（`no_identity` / `needs_cert` / `active`）、好友数、待发数与暂停的 kind。

| 操作 | 作用 |
| --- | --- |
| `friends`（读） | 互认的好友（`includePending` 带上待互认与冲突的），合并 `profile`、`friends/card`（逐字段 `profile` 优先）与本地备注；每行带 `avatar`（`content/<sha256>` 指针或 `null`） |
| `records`（读） | 按 `kind`、`author`、`id`、`cursor` 读好友分享的记录，不读 `binding` |
| `publish` | 发布 `{ kind, id, body, audience? }`；同作者同内容不重发，换作者重发 |
| `set-card` | 发布本机社交名片 `friends/card` / `self`：`{ name, emoji?, color?, avatar? }`，`avatar` 只收 `content/<sha256>` 指针（至多 5 MiB），`null` 清除；与 `publish` 同一条队 |
| `send-dm` | 发一条私信 `friends/dm`：`{ to, id?, text?, attachments?, replyTo? }`，受众只有 `to` 一人（不收 `public`、不收自己）；结果带最终用的 `id` |
| `post-feed` | 发一条动态 `friends/feed`：`{ id?, text?, media?, audience? }`，`audience` 缺省 `['public']`，写了须是 1–500 项（去重）；结果带最终用的 `id` |
| `retract` | 撤回一条，或省略 `id` 撤回本机在这个 `kind` 下的全部（含队列里还没发出去的） |
| `outbox`（读） | 待发与已同步条目的状态，从不给出 `body` |

- `publish`、`retract` 拒绝保留类型 `binding`、`profile`、`friends`、`coda/profile`、`coda/friends`；`kind` 须是 Accord 的格式，`id` 至多 200 个字符、256 字节，`body` 是对象且 JSON 至多 64 KiB，`audience` 每项是 `public` 或 `ed25519:` 加 64 位十六进制，至多 500 项。
- 没有身份、证书过期（或发布遇到 `invalid_state`）、`kind` 被暂停、发布失败时，待发的 `body` 暂存在本机 `outbox.json`；同步成功就释放 `body`，只留去重用的 `lastAuthor`、`lastSyncedHash`、`lastSyncedAt`；撤回完成就删掉条目。证书恢复后自动补发、补撤；待撤的条目记着排队时的作者（`targetAuthor`），换了作者不会替新作者撤，没有身份时的撤回只清本机未发出的待发，不排待撤。意图先落盘再签名，签名成功立即落盘确认；`outbox.json`、`policy.json` 读不出来（不是缺失或损坏）就报错，不当空表。
- 操作名照协议包的规定用小写加连字符（`set-card`、`send-dm`、`post-feed`）。
- 暂停与恢复某个 `kind` 的外发：`coda self policy.setKind '{"kind":"…","paused":true}'`，`coda self policy.get` 读现状（`policy.json`）；暂停只拦发布，不拦撤回。

## 私信与动态

两类记录都由 Accord 签名与保存，网关只清洗与投影，没有第二套目录库；没有身份或证书过期时在 `outbox.json` 排队、恢复后补发，撤回统一走 `retract({ kind: 'friends/dm' | 'friends/feed', id })`。

- **正文**：`text` 按原样（含首尾空白）至多 8000 个字（码点，与 schema 的 `maxLength` 一致），发布时去首尾空白；图片指针（`attachments` / `media`）1–4 个，只收 `content/<sha256>`；两者不能都空。`id` 省略时网关生成 UUID，给了须是至多 200 个字符、且 UTF-8 至多 256 字节（与 Accord 一致；schema 表达不了字节数，超了由网关以 `invalid_input` 拒绝）、不含控制字符，去首尾空白后不能为空；`replyTo` 同。
- **只发给别人**：私信的 `to` 不能是本人。排队时还没有身份、后来绑定的身份正好是收件人的，补发时按实际签名的作者再判一次，标成被拒（`error`），不签。
- **幂等重试**：`body.createdAt` 先沿用同一 `id` 已有的：`outbox.json` 里待发条目的，或已同步条目留下的 `lastCreatedAt`；队列里没有才查本机在 Accord 里的那条，查明没有才取当前时间，查询失败报可重试的 `unavailable`，不拿新时间戳重签。所以同一 `id`、同样内容的重试按 `publish` 的去重返回 `skipped: true`，不会重签。
- **投影**：每个 `(author, id)` 只取 `version` 最大的一条，它若是撤回（空 `body`）或畸形，整条就没了，不回落旧版本。私信只收本机发出（本人签、发给别人）或发给本机（别人签、`to` 是本人）的，`peer` 是对面那个人；串线、伪造的丢掉。私信按 `(createdAt, version, author, id)` 升序，动态降序。

### 实时流 `dm`、`feed`

两条都是 `read` 形状的帧流（`application/x-ndjson`，30 秒没东西写一个空行心跳），参数走查询串：`dm` 收 `peer`（只看与这位好友的），`feed` 收 `author`（只看这一位的），都收 `after`（上次拿到的游标）。

- 快照分片发出：每帧 `{ type: 'snapshot', cursor, items, more }`，单帧 JSON 至多 256 KiB（远低于 `readFrames` 默认的一行 1 MiB）；后面还有分片的 `more` 为 `true`，最后一片（空快照也有这一片，`items: []`）为 `false`。客户端把各片的 `items` 依次拼起来，收到 `more: false` 才落定整份快照与游标。
- 之后每次变化一帧 `{ type: 'upsert', cursor, item }` 或 `{ type: 'retract', cursor, author, id, peer? }`。同一条私信改投新收件人时，旧会话先收到 `retract`（`peer` 是旧收件人），新会话再收到 `upsert`。
- 游标是 `<epoch>:<seq>`：`epoch` 每次网关启动重新生成，`seq` 单调递增。网关在内存里留最近 500 次变化；`after` 有效时只补它之后的增量（含撤回，不重复）。`after` 缺失、不合法、来自上一次启动、比现在还新或已被挤出这 500 条的，回到全量快照。
- 只在有订阅者或新流连入时才翻页读 Accord，随本机 Accord 记录的变化和本机的发布、撤回刷新；刷新排成一条队，不会交错。每次都翻页读到底，读不全（翻页截断、查询失败）就不动内存里上一份完整的投影，不推虚假的快照或撤回；还从没读全过时新连入的流在第一个字节之前以 `unavailable` 失败。
- 调用方中止请求、取消应答体，或插件停用时，流当场收尾，订阅与监听随之释放（不等下一帧、也不管调用方读没读）。

## 权限与数据边界

- `friends/social@1` 的权限组：`read` 管 `friends`、`records` 和 `dm`、`feed` 两条流；`publish` 管 `publish`、`set-card`、`send-dm`、`post-feed`、`retract`、`outbox`。
- `uses`：`coda/accord@1` 的 `read`（读好友表与名片）、`publish`（发布名片）、`manage`（接受邀请、互认、移除）。`optionalUses`：`remote-exec/machine@1` 的 `use`（转给本机的远程执行，没装就没有这部分）。
- 保留种类 `friends/rpc-grant`、`friends/rpc-call`、`friends/rpc-answer`：只有本插件的内部入口能签发与读取，通用网关的发布、撤回、`records` 与帧流都不给出。
- 入网码（`authKey`）是凭据：只在提交时用一次，提交后立即清空输入框，不写入任何文件、日志或页面状态。
- 本地备注只存在插件自己的持久目录 `notes.json`（卸载后保留），不发给好友，也不进 Accord 目录。
- 好友发来的昵称、Emoji、颜色按同一套规则清洗，只当文本渲染（`textContent`），不当指令或 HTML。
- 好友页的 Accord 读写在页面交互时发起；模块只在 `activate` 时监听本机 Accord 记录（证书、好友表），用来刷新网关记录、证书恢复后冲洗待发队列。
- `uses` 的 `publish` 也供网关代别的插件向好友发布；待发的 `body` 只在本机 `outbox.json`，不经别处。
