# 好友

管理本机的 Accord 身份与熟人好友通道（`coda/accord@1`），并提供业务无关的好友网关（`friends/social@1`）。

- **本机身份**：身份卡显示本机的展示名、确定性几何纹头像、公钥短码（点按复制），下方状态条给出已互认好友数（有待互认、冲突时提示）与身份、证书状态。没有建身份时显示「未建身份」并提示前往客户端「设置 › 身份」创建。
- **公钥派生的昵称与头像**：本机和好友都没有可编辑的昵称、照片、Emoji 或主题色，统一由 Accord 公钥推出。展示名是 `昵称 #尾号`：昵称按 coda#3040 的算法取公钥 256 位，从最高位起每 7 位一组（至多 36 组），`0–77` 为字母、`78–87` 为数字、`88–127` 为结束符（已有不足 2 位时跳过，够 2 位就结束，读完仍不足 2 位则没有昵称）；尾号是公钥按大端整数转成十进制（补零到 78 位）后的末 4 位。解不出昵称时退回公钥短码（`ed25519:` 之后前 8 位），还没有公钥的待互认好友用节点名。头像是由公钥确定性生成的 5×5 几何纹，灰色，换设备也一样；没有合法公钥时取名字首字。算法在 `lib/nickname.mjs`，浏览器与 Node 通用。
- **添加好友**：点身份卡上的「添加好友」，粘贴对方给的邀请（JSON、`coda-friend://` 链接或多行 `key=value`），接受后自动尝试互认。暂需由对方提供 friend 角色入网码。
- **好友列表**：实时跟随好友表变化，宽屏双列。点好友打开详情：昵称、几何纹头像、完整公钥（可复制）、节点名、连接状态、重新互认、二次确认后移除。
- **社交网关 `friends/social@1`**：业务无关，别的插件（在 `optionalUses` 里声明）经它读好友与好友分享的记录、向好友发布与撤回记录，不必各自处理没有身份、证书过期和重试。

## 几台电脑

页面不自己选电脑：App 的全局视图里有哪几台，页面就读哪几台，没有机器标签。

- **本机身份按公钥显示**：按各台 Accord 的 `spec.author` 分组，同一身份只显示一张身份卡，视图里有不同身份的电脑时每个身份一张。
- **好友按电脑分节**：每台一节，顺序同视图，节标题是电脑名；节里是这台自己的好友通道（好友关系按机器上的通道登记，在 A 上加的好友 B 上不会自动出现），状态条（好友数、证书状态、待互认与冲突）和「添加好友」也在这一节。接受邀请与随后的互认、好友详情里的重新互认、移除，都发给这一节、这一行所在的电脑。没有好友的电脑也占一节；同一个好友在两台上都加了，就在两节里各出现一次，不合并。读不到的电脑（`unreachable`）节里写明原因，不出「添加好友」。
- **只有一台时**页面不出现节标题，状态条与「添加好友」仍在身份卡上。
- **推荐用法**：好友只在一台电脑上加。好友关系登记在那台电脑上，别的电脑不会自动出现这个好友。邀请里的入网码只能用一次，不必在每台上重复加。
- **几台电脑绑定同一个身份、又在同一个空间里时**，其他电脑发布的记录由 Coda 在这几台之间同步，好友从加了他的那台读取（见 Coda 仓库 `docs/peers.md`）。这是 Coda 基座的行为，本插件不另外保证，也不检查同步是否已经完成。

## 社交网关

签名写入与记录查询全部透传 `coda/accord@1`，网关自己没有第二份目录库。本机网关记录（`friends/social@1`，key `local`）的 `status` 给出作者、证书状态（`no_identity` / `needs_cert` / `active`）、好友数、待发数与暂停的 kind。

| 操作 | 作用 |
| --- | --- |
| `friends`（读） | 互认的好友（`includePending` 带上待互认与冲突的），只来自 Accord 的好友表：`{ selfAuthor, certState, friends }`，每行的 `title` 是公钥派生的展示名，不读名片记录 |
| `records`（读） | 按 `kind`、`author`、`id`、`cursor` 读好友分享的记录，不读 `binding` |
| `publish` | 发布 `{ kind, id, body, audience? }`；同作者同内容不重发，换作者重发 |
| `retract` | 撤回一条，或省略 `id` 撤回本机在这个 `kind` 下的全部（含队列里还没发出去的） |
| `outbox`（读） | 待发与已同步条目的状态，从不给出 `body` |

- `publish`、`retract` 拒绝保留类型 `binding`、`profile`、`friends`、`friends/card`、`coda/profile`、`coda/friends`；`kind` 须是 Accord 的格式，`id` 至多 200 个字符、256 字节，`body` 是对象且 JSON 至多 64 KiB，`audience` 每项是 `public` 或 `ed25519:` 加 64 位十六进制，至多 500 项。
- 没有身份、证书过期（或发布遇到 `invalid_state`）、`kind` 被暂停、发布失败时，待发的 `body` 暂存在本机 `outbox.json`；同步成功就释放 `body`，只留去重用的 `lastAuthor`、`lastSyncedHash`、`lastSyncedAt`；撤回完成就删掉条目。证书恢复后自动补发、补撤；待撤的条目记着排队时的作者（`targetAuthor`），换了作者不会替新作者撤，没有身份时的撤回只清本机未发出的待发，不排待撤。意图先落盘再签名，签名成功立即落盘确认；`outbox.json`、`policy.json` 读不出来（不是缺失或损坏）就报错，不当空表。
- 旧版留在 `outbox.json` 里的保留类型条目（如已下线的名片 `friends/card`）读表时直接丢掉，随启动或下一次冲洗落盘清理，不补发、也不挡着别的待发条目。插件不会去撤回 Accord 里历史上已发布的旧名片记录。
- 暂停与恢复某个 `kind` 的外发：`coda self policy.setKind '{"kind":"…","paused":true}'`，`coda self policy.get` 读现状（`policy.json`）；暂停只拦发布，不拦撤回。

## 已下线的功能

名片编辑（昵称、照片、Emoji、字标、主题色、裁剪上传）、本机备注（`notes.json`、`coda self notes.*`）、`set-card`、私信 `send-dm`、动态 `post-feed` 与 `dm`、`feed` 两条帧流都已移除。插件本地只写 `outbox.json` 与 `policy.json`；旧版留下的 `notes.json` 不再被读取。

## 权限与数据边界

- `friends/social@1` 的权限组：`read` 管 `friends`、`records`；`publish` 管 `publish`、`retract`、`outbox`。
- `uses`：`coda/accord@1` 的 `read`（读好友表）、`publish`（网关代别的插件发布）、`manage`（接受邀请、互认、移除）。
- 入网码（`authKey`）是凭据：只在提交时用一次，提交后立即清空输入框，不写入任何文件、日志或页面状态。
- 节点名等外来数据只当文本渲染（`textContent`），不当指令或 HTML。
- 好友页的 Accord 读写在页面交互时发起；模块只在 `activate` 时监听本机 Accord 记录（证书、好友表），用来刷新网关记录、证书恢复后冲洗待发队列。
- 待发的 `body` 只在本机 `outbox.json`，不经别处。
