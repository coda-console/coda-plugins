# Ultra

输入框的 Ultra 协调模式（Coda 的[输入框模式](https://github.com/coda-console/coda/blob/main/docs/plugins.md#输入框模式)）：开着时，主 Agent 负责理解需求、拆解任务、调度和验收，
实现、深入排查、编写测试、运行测试或构建及失败修复都按名单用 `spawn` 派给 Coda 子会话。关键路径和需要串行执行的任务也委派，结果自动回来后由主 Agent 检查证据、安排返工并汇总。

从 Coda 的商店安装（npm 包 `@coda-console/ultra`，分类「工作流程」），不随 Coda 默认装上。Coda 不认识 Ultra：模式、参数、给 Agent 的话都在这个插件里。

**用法**：会话或新任务的输入框里打 `/ultra`（或在 `/` 菜单、iPhone 的「+」里选），输入框进入 Ultra；在新任务里进入，发出第一条后开出的会话就在 Ultra 里，模式条上写着所选的模板和名单里 Agent 的图标；点模式条打开参数：

| 参数 | 是什么 |
| --- | --- |
| 模板 | 设置 `ultra.templates` 里的模板，加「自定义」；选一个就把名单换成它的，手动改了名单就变成「自定义」。进入时取排第一的模板；没有模板时为「自定义」，名单为空 |
| 子 Agent | 名单，一行一个：Agent 组合（Agent、模型、推理强度、配置项）和「什么时候派给它」。名单为空或名单里没提到的活，Agent 用自己的 Agent 和模型派 |

模式开着时发的每条消息照常发给这个会话，工具栏上的 Agent 和模型不变；点 × 退出。

**告诉 Agent 什么**（`ultra.mjs`，经 Coda 的「顺带告诉」随下一轮带上）：

- 开着后发的第一条，以及参数改过之后的第一条：进入协调模式，原先「没要求就别派」不再适用；用户明确修改规则时优先，普通的实现请求不算解除协调职责。附上名单，一行一个，写成 `spawn` 要的 `agent`、`model`、`effort`、`mode`、`options`。
- 主 Agent 制定计划、约定接口和验收标准、选择执行者、检查结果证据、安排返工并汇总。为调度和验收做少量定向阅读、只读抽查可以；实现、深入排查、编写测试、运行测试或构建及失败修复交给子会话，关键路径也一样。主 Agent 不编辑交付文件，也不以集成或验证为由接回执行任务。
- 子任务具体、自包含，给出验收标准和不与其他执行中会话重叠的写入范围。主 Agent 在交接任务里明确子会话是执行者，自己完成任务，不继承主会话的纯协调职责；没有明确指派就不继续转派，获准转派也走 Coda。结果自动回来，主 Agent 不重做。
- 委派只走 Coda 的 `spawn`，即使用自己的 Agent 和模型，也创建 Coda 子会话；除非用户明确要求，不用运行时自带的子 Agent 或委派工具。
- 之后每 10 条提醒协调职责、关键路径也委派、子会话负责执行，以及并发满时等待、不可用时报阻塞和只走 Coda 的规则。
- 名单写得太长、连同说明超过 Coda 一次能告诉 Agent 的长度（4000 字）时，那条消息发不出去，界面说明原因；改短后再发就照常告诉。
- 退出时撤销 Ultra 的纯协调职责和「委派只走 Coda」限定，恢复通常的执行与委派指令，Coda 子会话回到「有要求才派」；一条都没发过就不说。

同时在跑的子会话有多少由 Coda 管（「会话生命周期」插件的设置「同时执行的子会话」），满了 `spawn` 当场失败。
并发已满时等已有 Coda 子会话结束、腾出名额；`spawn` 不可用时说明阻塞，只继续不依赖它的协调工作。两种情况都不接手执行任务或改用原生子 Agent。
这些职责和委派渠道仍是提示词约束，插件没有在运行时禁用主 Agent 的执行工具或原生子 Agent 工具。

**设置** `ultra.templates`：一列行，每行「模板名、Agent、什么时候派给它」，同一个模板名的几行是一个模板。默认不带模板，子会话沿用当前会话的 Agent 和模型；用户可以自行添加、修改、删除模板。

测试在 `test/plugins/ultra/`。
