# Ultra

输入框的 Ultra 模式（Coda 的[输入框模式](https://github.com/coda-console/coda/blob/main/docs/plugins.md#输入框模式)）：开着时，主 Agent 主动把能并行的活拆出去，
按名单用 `spawn` 派给 Coda 子会话，自己做卡住的那一步，结果自动回来后汇总、验证。提示词与时机参照 Codex 的 `ultra` 推理档（主动多 Agent 委派）和 Claude Code 的 Ultracode。

从 Coda 的商店安装（npm 包 `@coda-console/ultra`，分类「工作流程」），不随 Coda 默认装上。Coda 不认识 Ultra：模式、参数、给 Agent 的话都在这个插件里。

**用法**：会话或新任务的输入框里打 `/ultra`（或在 `/` 菜单、iPhone 的「+」里选），输入框进入 Ultra；在新任务里进入，发出第一条后开出的会话就在 Ultra 里，模式条上写着所选的模板和名单里 Agent 的图标；点模式条打开参数：

| 参数 | 是什么 |
| --- | --- |
| 模板 | 设置 `ultra.templates` 里的模板，加「自定义」；选一个就把名单换成它的，手动改了名单就变成「自定义」。进入时取排第一的模板；没有模板时为「自定义」，名单为空 |
| 子 Agent | 名单，一行一个：Agent 组合（Agent、模型、推理强度、配置项）和「什么时候派给它」。名单为空或名单里没提到的活，Agent 用自己的 Agent 和模型派 |

模式开着时发的每条消息照常发给这个会话，工具栏上的 Agent 和模型不变；点 × 退出。

**告诉 Agent 什么**（`ultra.mjs`，经 Coda 的「顺带告诉」随下一轮带上）：

- 开着后发的第一条，以及参数改过之后的第一条：打开主动委派，原先「没要求就别派」不再适用，用户在消息里说的优先；怎么拆（先定计划、卡住的那步自己做、子任务具体自包含、写入范围不重叠、派出去后做自己的、不重做）；名单，一行一个，写成 `spawn` 要的 `agent`、`model`、`effort`、`mode`、`options`。
- 委派只走 Coda 的 `spawn`，即使用自己的 Agent 和模型，也创建 Coda 子会话；除非用户明确要求，不用运行时自带的子 Agent 或委派工具。
- 之后每 10 条提醒「仍在开着，委派只走 Coda，除非用户明确要求原生子 Agent」。
- 名单写得太长、连同说明超过 Coda 一次能告诉 Agent 的长度（4000 字）时，那条消息发不出去，界面说明原因；改短后再发就照常告诉。
- 退出时撤销 Ultra 的「委派只走 Coda」限定，恢复通常的委派指令，Coda 子会话回到「有要求才派」；一条都没发过就不说。

同时在跑的子会话有多少由 Coda 管（「会话生命周期」插件的设置「同时执行的子会话」），满了 `spawn` 当场失败。
`spawn` 不可用或并发已满时，提示词告诉 Agent 自己做或等已有 Coda 子会话做完，不改用原生子 Agent。这是提示词约束，插件没有禁用运行时的原生工具。

**设置** `ultra.templates`：一列行，每行「模板名、Agent、什么时候派给它」，同一个模板名的几行是一个模板。默认不带模板，子会话沿用当前会话的 Agent 和模型；用户可以自行添加、修改、删除模板。

测试在 `test/plugins/ultra/`。
