# 网络记录

按需采集，**默认关闭**。在「设置 › 插件 › 网络记录」打开「采集网络记录」，才在这台机器后台记录；排查结束后关闭。
开关不要求重启后端，也不用开着页面。关闭后不再读取连接表、发起定时探测或查询 mihomo，只检查本机的采集设置；
已经发出的操作返回后不再写入采集结果，观察中的连接记为「记录中断，结局未知」。页面和 `network-log` 命令仍可查历史，打开它们不会开启采集。
开关属于机器，目录里的停用或设置覆盖不控制后台采集。空间插件设置选「全部」可一起修改各台，选一台就只改那台。
数据只存在采集的机器上，保留 30 天；关闭后也照常清理过期记录。

目前只记录 TCP 建连等待与配置地址的独立探测，不是完整的网络故障诊断：未记录不代表网络正常，探测结果也不代表实际请求的结果。

## 记什么

- **建连卡住**：每秒读一次这台机器的连接表（macOS `netstat`，Linux `ss`，系统自带、不用 root），
  一个连接停在建连阶段（已发出、没有回应）超过设置的秒数（默认 3 秒），就记一条：
  - 哪个进程、它的命令行（如 `git-remote-https https://github.com/…`）；
  - 连向哪里、从哪个本地地址出去、走的哪张网卡（macOS 上再用 `nettop` 读一次，拿到完整地址和网卡）；
  - 这台有 mihomo 时：这张网卡是不是 mihomo 的虚拟网卡，mihomo 那一刻有没有收到这条连接、走哪个节点；
  - 后来连上了，还是放弃了（进程超时或结束），用了多久。

  任何程序的连接都在表里：Agent 跑的命令、Coda 后端自己的 git、你在终端里跑的程序都一样。
  不到一秒就结束的失败（马上被拒绝、被重置）可能落在两次读表之间，这类失败会立刻报出明确的错误。
- **定时探测**：每分钟请求一次设置里的地址（默认 GitHub、GitHub API、npm），用系统的解析器、自己的连接，
  分段记下解析、建连、TLS 与首字节的耗时；失败时记在哪一段、系统怎么说（`ENOTFOUND`、`ECONNRESET`、超时……），以及解析到的地址和走的网卡。
  它是基准时间线，也覆盖连接表看不到的 DNS。

## 看

- **页面**：资源页里的「网络记录」，一页看空间里每台机器。上面选时间段（1 小时、24 小时、7 天）；
  「建连卡住」按时间列出每一条，「定时探测」每个地址一条色块时间线（绿是都通，橙是有失败，红是全失败），下面是最近几次失败。
- **命令**：会话里的 Agent 和 shell 有 `network-log`，读这台机器的记录：

  ```
  network-log                       最近 24 小时的建连卡住与探测失败
  network-log --since 2h            最近 2 小时
  network-log --from 2026-10-24T02:00 --to 2026-10-24T05:00
  network-log --hangs               只看建连卡住
  network-log --probes              列出每次探测（含成功的）
  network-log --json                每个记录一行 JSON
  ```

## 设置

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 采集网络记录 | 关闭 | 按需开启，关闭后停止采集并保留历史；在机器的插件设置中修改 |
| 定时探测 | GitHub、GitHub API、npm | 一行一个地址，行名是显示的名字 |
| 建连多久算卡住（秒） | 3 | 1–60 |
| mihomo 控制接口 | `http://127.0.0.1:9090` | 没有 mihomo 时清空；控制接口不能设 secret |

## 要求

Coda 支持插件启动即载入（`activationEvents`）的版本，才会在不开页面时也应用采集开关；更早的版本只在页面打开后检查开关。
读连接表支持 macOS 与 Linux；别的系统只做定时探测。记录在插件的状态目录（`<状态根>/plugins/network-log/log/`），一天一个文件。
