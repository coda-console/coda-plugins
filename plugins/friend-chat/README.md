# 好友对话（原型）

和已经互认、并且双方都绑了个人身份的好友收发文字消息。消息是 `coda/accord@1` 签名的记录，插件把它们投影成 `coda/session@1` 会话，所以在 Coda 的会话列表里像别的外部会话一样读、发、提醒。

## 职责边界

- **只给本机客户端**：`read`、`post`、`draft` 只接 Coda 宿主转来的本机客户端调用；本机别的插件来调（`caller.plugin` 不是本插件）一律 `forbidden`（`effects: none`）。
- **只做对话**：好友关系、邀请、互认、身份与证书都归 Coda 的 Accord 和「好友」插件，本插件只读 `coda/accord@1` 的本机记录（`status.certificate`、`status.friends`），从不改它们。
- **只认个人身份**：本机必须以个人根钥匙签名（`status.certificate.root`，且 `spec.author` 就是它），对方也必须是绑了个人身份的好友（好友表里同一公钥至少一条通道已互认、无冲突、`certified: true`）。机器钥匙裸绑、未互认或通道冲突的好友不建会话，他们发来的消息也不收。只有本机此刻能签名（证书在有效期内）时才收新记录，且只收此刻可对话的好友的（本人另一台设备发的也要对方此刻可对话）；失格或证书失效期间晚到的记录不入库、不推进 `head`，也不会为没有历史的对端建会话，等恢复后的同步再收。
- **单聊会话**：两个公钥之间一个会话，ID 是 `dm:` 加两把公钥排序后 SHA-256 的前 32 位十六进制，对称、确定，不含通道。会话记录的 key 是 `<本机个人身份>:<对方公钥>`，`spec.container` 是本机个人身份，名字和头像都由公钥推出（与「好友」页同一套算法）。
- **只发文字**：`post` 收到图片、语音等媒体片段，或带 `replyTo`、非空 `mentions`，回 `unsupported`（`effects: none`），不静默丢掉；收到的附件指针照协议透给读的一方，不在这里取内容。

## 消息：`friend-chat/event` 不可变信封

每条消息一条 Accord 记录，种类 `friend-chat/event`（只归本插件），记录 ID 是 `<会话 ID>/<事件 ID>`，`audience` 只有对方，发布时带 `expectAuthor`（本机个人身份），署名不符 Accord 拒签。记录体：

```json
{ "v": 1, "conv": "dm:…", "id": "<事件 ID>", "type": "message", "sentAt": 1700000000000, "text": "你好", "parts": [{ "type": "text", "text": "你好" }] }
```

- **事件 ID** 由 `post` 调用的 ID 派生（UUID 形状）：插件同一次运行里同一个调用 ID 重来发布同一条，不会多出一条。插件不登记 `resume`：重启时还在进行的 `post` 由宿主记为 `interrupted` 或结果未知（`unknown`），不续跑；若那条当时已经发出，重启后经 Accord 的 watch 同步照样补进历史。
- **`sentAt`** 是发送方的时间，只用于显示（`createdAt`）。
- **记录的 `version`** 是签名者自己的时间：离线的好友后来补同步上来的旧消息，`version` 可能比本机刚发的新消息还小，排在列表更后面。所以每次同步都沿 `nextCursor` 翻完全部页（游标重复即停），按「作者 + 事件 ID」跳过已入库的，不按最大 `version` 提前停。翻完后把这轮的新消息按 `sentAt`、`version`、作者、事件 ID 正序入库，离线期间连发（哪怕跨页）的几条按发送先后排。
- **本人另一台设备**（同一空间、同一个个人身份）发出的消息作者是自己：按记录里的 `conv` 反查对方（此刻可对话的好友），照样入库。

## 本机投影与 `localSeq` 游标

消息存在插件状态目录 `roots/<个人身份的哈希>/<会话的哈希>.json`（目录 0700、文件 0600，临时文件加 rename 原子替换），按个人身份分开。每条消息入库时拿会话内严格递增的 `localSeq`（从 1 起），补进来的旧消息也拿新的更大序号，所以：

- `read` 的游标就是 `localSeq`，消息按入库先后排，`after`、`before`、`limit` 照 `coda/session@1`；一页的 JSON 另限 768 KiB（宿主信封上限 1 MiB），放不下时最新页与 `before` 页少给较旧的、`after` 页少给较新的，至少一条，`more` 为 `true`；没有消息的页（含 `after` 之后没有新的）`cursor` 为 `null`；
- 会话记录的 `status.head` 是最新的 `localSeq`，有新消息就一定前进；`post` 返回的 `cursor` 与 `head` 一致，Accord 的 watch 抢先入库了也不会重复。

## 会话状态与 `unreachable`

| 情形 | 有本地消息 | 没有本地消息 |
| --- | --- | --- |
| 本机个人身份证书有效，对方可对话 | `active` | `active`（空会话，可直接发） |
| 解除好友、未互认、冲突、对方没绑个人身份 | `unreachable`，写明原因 | 不建（已建的撤下） |
| 证书过期或未生效 | `unreachable`，写明原因 | 不建（已建的撤下） |
| 换了个人身份、解绑了个人身份 | 原身份下的会话 `unreachable` | 不建 |

`unreachable` 的会话照旧能读历史；`post` 在发布之前就以 `invalid_state`（`effects: none`）拒绝。证书的有效期是 `from` 到 `until`（含两端）。证书生效、自然到期时 Accord 不推送变更，插件在还没到 `from` 时于 `from` 重读，在有效期内于越过 `until` 时重读，再算一轮。会话记录在启动时整份 `replace`（清掉上次运行留下的），之后只写变了的。

启动时的首次同步失败，插件撤下已登记的处理函数、服务与 watch，把错误交给宿主；之后的同步暂时失败则 5 秒起翻倍退避重试（封顶 60 秒），成功或停用时清掉。

## 头像

插件登记流式服务 `avatar`，路径 `ed25519/<64 位十六进制公钥>.png`，`GET`、`HEAD` 给由公钥确定性生成的 96×96 PNG 几何纹（长期缓存）；别的方法 `405`，路径不对或带查询串 `404`。会话参与者的 `avatar` 是指向它的指针。
