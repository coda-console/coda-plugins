# Token 消耗榜

看本机的 Token 用量，并和好友比一比。**向好友分享用量默认开启**，可以在页面或插件设置里关闭。

## 权限

只申请最小权限，不申请 `manage`：

- `coda/usage@1` `read`：读本机按十分钟、人、Agent、模型身份（模型服务、请求的模型、实际型号）汇总的 Token 数与回合数（不含会话、目录、正文、费用）。
- `coda/machine@1` `read`：只读本机的机器 ID，当作稳定的来源 ID（不读机器名等其他信息）。
- `friends/social@1` `read`（**可选**，写在 `optionalUses`，不是硬依赖）：经好友插件的网关读本机身份、已互认的好友，以及好友发来的 `coda/token-day`、`coda/token-today` 与旧版 `coda/token-usage` 用量记录；不读好友名片。
- `friends/social@1` `publish`（**可选**）：只在开启分享后，经网关发布本机的 `coda/token-day` 与 `coda/token-today` 记录，撤回时逐条（带记录 ID）撤回。
- `magpie/models@1` `read`（**可选**，写在 `optionalUses`）：读本机 Magpie 插件的同型号映射（只读的安全查询 `names`），见下面「型号与请求项」。没装 Magpie 插件、读不到或超时（10 秒）都当没有映射，行为与不映射完全相同。

没装或停用好友插件时，本机统计与 48 小时曲线照常运行、零报错，分享状态显示「未安装或未启用好友插件」（`no_gateway`）。

## 分享什么

向好友分享用量开启时，每 10 分钟经好友网关发布两种记录（默认发给你的好友），内容没变由网关按规范哈希去重、不重发：

- **月块日归档** `kind: coda/token-day`，`id: <sourceId>/<YYYY-MM>`，记录体 `{ v: 3, days: { "YYYY-MM-DD": { [agent]: [ { a, s, u, i, m, n } ] } } }`（一行的写法见下），按 UTC 日汇总，发布最近约 30 天所在的月份。一个月超过 60 KiB 时拆成 `<YYYY-MM>-1`（1–15 日）与 `-2`（16–31 日），再超按周 `-w1`…`-w5`，最后合并小型号。
- **48 小时滚动曲线** `kind: coda/token-today`，`id: <sourceId>`，记录体 `{ v: 3, slotMs, windowStart, windowEnd, slots: { "<槽起点毫秒>": { [agent]: [ { a, s, u, i, m, n } ] } } }`，默认 30 分钟一槽（超 60 KiB 降为 60 分钟一槽），每次覆盖同一条。
- **一行** `{ a, s, u, i, m, n }`：`a` 请求的模型 ID（`asked`），`s` 实际型号（`served`），`u` 同型号映射归并后的名字（可选，没有归并就不写，见下；不混进 `a` 或 `s`），`i` 模型服务的接口种类（如 `openai-responses`，**不带服务的 UUID**，别人机器上的资源 ID 好友用不上也不该拿到），`m` 未分层的旧标签（只在没有分层信息的行上，与 `a`、`s`、`u`、`i` 不同时出现），`n` 是 `[input, output, cacheRead, cacheWrite, turns, reportedTurns]`；没有的不写。后端允许只带服务的行，这样的行只有 `i`，型号名取服务的接口种类名。`a`、`s`、`u`、`m` 是身份：读写都原样保存、按字符串完全相等比较（不压缩空白），边界上只验类型与长度（1–200 字、不含 NUL），不合法的行整行丢弃；清洗只在页面显示时做。写记录时各行原样保留，包括只有回合数的请求行，不预先分配回合。
- **体积预算**：记录体不超过 60 KiB。放不下时按型号名（见下）逐级折叠：每个 Agent 只留 Token 最多的 32、8、2、1、0 个型号（并列取名字靠前的），其余各行并成一行 `m: "other"`；0 个也放不下就把每格所有 Agent 和型号合成 Agent `_` 下的一行 `m: "_"`，只留总量。折叠不改总量（含回合数），结果与输入顺序无关。
- **读取端**同时认旧版：`v: 2`（每个型号一个旧标签：`{ [agent]: { [model]: [6 个数] } }`）与更早的 `coda/token-usage`，旧记录按旧标签显示。
- `sourceId` 优先取 `coda/machine@1` 里本机的稳定机器 ID；读不到就沿用 `source.json` 里已有的（没有才生成一次随机 UUID），不会因为一时读不到换新 ID。从随机 UUID 换成机器 ID 后，旧 UUID 记在 `source.json` 的 `legacy`：榜单里不再把它名下的旧记录当成另一台机器，开启分享同步或撤回时也会逐条撤回它留下的旧记录。
- 不含机器名、会话、目录、正文和费用。0.1.0 发布的 `coda/token-usage`（`<UTC 日期>/<sourceId>`）只做过渡期兼容读取与撤回：某台机器只要有新版记录，就不再读它的旧版记录，不会双计。
- 关闭分享或点「撤回已发布的记录」，会先按本机 `sourceId`（及 `legacy` UUID）筛出自己的记录 ID，再逐条经网关撤回，好友不再看得到；**绝不按 kind 批量撤回**，同一作者其他设备的记录不会被误撤。撤回还会取消好友网关里排着的本机待发项（没有身份时也一样），免得恢复身份后把已撤回的用量发出去。没装好友插件时撤回不会假装成功，会保留本机已发 ID 的索引，装回后再撤；整轮没全部确认撤回（排了队、查询被截断、出错）时索引原样保留，等下次重试。同步里发布或必需的撤回只要有排队、暂停、需要证书、没身份或出错的，就不报「已同步」、不刷新上次同步时间。

统计和发布互不阻塞：没有好友插件、没有身份、没开分享、24 小时代签证书过期或好友插件暂停了这类数据的外发时，本机统计、多机合并和当天曲线照常显示。证书过期、暂停等由网关在本机排队，恢复后自动补发；同步状态如实显示为 `no_gateway`、`no_identity`、`needs_cert`、`paused`、`queued`、`synced` 或 `error`，页面只显示一条轻提示。

## 型号与请求项

用量行的模型身份有三层：模型服务（`service`）、请求的模型（`asked`）、实际型号（`served`），旧数据只有一个未分层的标签（`model`）。榜单的分模型明细这样算：

- **型号名**（`lib/usage.mjs` 的 `modelName`，全插件只此一处）：`served`，没有取同型号映射归并后的名字 `same`（见下），再没有取 `asked`，再没有取旧标签 `model`。名字相同的行合成一行（旧标签行与分层行同名也合）。只带服务的行没有这几项，取服务的接口种类名。不建全局型号表，不猜实际型号，不回填旧数据。
- **同型号映射**：经 Magpie 走的请求拿不到实际型号（`served` 为空），请求的模型 ID 形如 `group/ds-flash`、`opencode-go/deepseek-v4.1-flash`。装了 Magpie 插件时，取数（页面读榜单、同步发布）开头向它读一次映射 `{ "<asked>": "<底层型号名>" }`（规则与怎样在 Magpie 里声明同型号见 Magpie 插件的 README；
  **手建组要所有成员的底层型号名都相同才归并**，否则它保持自己的名字单独一行），再套到本机行上：`asked` 命中、`served` 为空、行的 `service` **是本机 Magpie 插件提供的服务**（映射连同这些服务的资源引用一起返回）的，型号名取映射后的名字；有 `served` 的行、旧标签行，以及走别台或别的插件提供的服务的行都不套（A 机的 Agent 用 B 机的 Magpie 服务是常见用法，那些行的 `asked` 是 B 机 Magpie 里的名字）。
  展开型号行仍按原来的 `asked` 与接口种类列请求项，所以 `group/ds-flash`、`opencode-go/deepseek-v4.1-flash` 各是一项。
  映射属于提供模型服务的那台机器：**每台机器只对自己本机的行套自己的映射**，套出的名字写进它发布的记录（行里的 `u`，没有归并就不带），读取端读到就用它当型号名，不拿本机的映射去套别人记录里的行；同一空间里别的机器由那台的插件套好后经记录或回包交回。
  没装 Magpie 插件、没有映射或读不到时，与不映射完全一样。
- **请求项**：型号行名下按（`asked`，服务的接口种类）分开列出，页面点开型号行就能看到各项的 Token 与回合。只有一个请求项、它的 `asked` 就是型号名、又没有服务时不可展开。
- **回合**：轮数记在请求行（没有 `served` 的行）上，Token 可能在带 `served` 的行上。只在读取端的聚合（`Tally`）里分配一次，范围是当次查询窗口，本机与签名记录读回后走同一段聚合。同一请求项的请求行只有轮数没有 Token 时，轮数记到该请求项下 Token 最多的型号行（并列取名字靠前的）；请求项下没有带 Token 的型号行，就留在请求行。型号行的回合数是它名下请求项之和，同一轮只算一次；作者的总回合数是所有行相加，不受归并影响。

## 谁的用量

后端的用量按人（`person`，这台后端的根身份）分开记，同桶不同身份的行不相加。只有 `person` 是当前身份（好友网关给出的本机作者）或空字符串（没有身份的行）的本机行，才算作当前作者的用量：页面概览、榜单、当天曲线和经网关发布的记录都是这样，别的身份的行不计入也不发布。读不到身份（没装好友插件）时没有作者可归属，本机统计不按身份切、照常显示；有网关但还没有身份时，交给网关排队的记录只含无身份的行。

## 看什么

页面（资源页里的「Token 消耗榜」）：时间范围（今天 / 近 7 天 / 近 30 天），本机概览，和熟人消耗榜（可展开看分模型明细，型号行还能再展开看请求项）。同一好友身份下的多台机器合并计入「我」；模块同时算好本地「今天」按 30 分钟切的合并曲线（`board.curve`）。

### 几台机器

页面不自己选机器：App 的全局视图里有哪几台，页面就读哪几台（时间范围一次作用于整页），按人合并：

- 榜单一个人一行。各台的 `board` 回包带 `sources`（每个作者名下每个来源 `sourceId` 的合计，`local` 标出哪个是这台自己的本机数据）、`retired`（这台已弃用的旧来源 ID）和 `people`（每人的作者地址、分享状态）；不再另发按作者聚合的统计。页面把各台的 `sources` 按（作者, 来源）并起来，同一个只算一次：有那台来源自己的本机数据就用它，否则先比当天曲线记录的版本 `todayVersion`（高的赢，一份有一份没有就有的赢；一个来源只有一条曲线、每次覆盖，不受归档分块影响），相同或都没有再比 Token 合计、回合数；`retired` 里的旧来源 ID 在同一作者下统一不要（不受本机用量读没读到影响）；再按作者汇总排序（`lib/merge.mjs`）。回包序列化后超过宿主 128 KiB 的消息上限时，回一个带请求标识的 `error`，页面把这台标成读不到。
- 用量按身份分块：同一好友身份的几台相加，标题写明合了哪几台；视图里有不同身份的电脑时每个身份一块；只有一台时仍写「本机」。
- 时间窗口：页面每一轮读取按正在看页面的这台设备的当地时间算一组 `from`、`to`（`lib/usage.mjs` 的 `rangeWindow`，语义同今天 / 近 7 天 / 近 30 天），随 `board` 请求发给每一台，后端按这组窗口算，各台时区不同也是同一段时间。
- 分享：视图里每一台都已回报、且状态一样才显示一份，否则按台列出，没回报或读不到的写明（工具栏的分享开关此时不出现）；开启 / 关闭、撤回、同步都对每台发（同步只发给开着分享的），逐台给结果，失败的标出是哪台。
- 读不到的机器（`unreachable`、请求或榜单失败，或那台装的是没有 `sources` 的旧版插件，需要更新）页面标出是哪台和原因；合计只含读到的，榜单和用量标题旁标「不完整」，还在等回包的标「读取中…」。本机用量查询失败的那台，`local` 为 null、不交出本机来源，页面写明合计缺它的本机用量。
- 开关和撤回对没连上的机器会写明它没有执行（撤回时提示它已发布的记录还在）。

用量概览和熟人榜用 Accord 公钥映射出的 ID 显示身份。同一个 ID 对应多个公钥时，每个 ID 都加上对应公钥的末四位十六进制，如 `leavan(3d2a)`。无法映射出 ID 时显示短地址。榜单里每个人都用默认头像。

用量不会推送，所以页面每分钟刷新一次，好友网关有变动（`friends/social@1`）时也会立即刷新。
页面上切的分享开关只在设置没再改动之前有效；在设置里改了分享开关，以设置为准。
