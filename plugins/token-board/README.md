# Token 消耗榜

看各台机器的 Token 用量，并和好友比一比。**向好友分享用量默认开启**，可以在页面或插件设置里关闭。

## 权限

只申请最小权限，不申请 `manage`：

- `coda/usage@1` `read`：读本机按十分钟、人、Agent、模型身份（模型服务、请求的模型、实际型号）汇总的 Token 数与回合数（不含会话、目录、正文、费用）。
- `coda/machine@1` `read`：只读本机的机器 ID，当作稳定的来源 ID（不读机器名等其他信息）。
- `friends/social@1` `read`（**可选**，写在 `optionalUses`，不是硬依赖）：经好友插件的网关读本机身份、已互认的好友，以及好友发来的 `coda/token-day`、`coda/token-today` 与旧版 `coda/token-usage` 用量记录；不读好友名片。
- `friends/social@1` `publish`（**可选**）：只在开启分享后，经网关发布本机的 `coda/token-day` 与 `coda/token-today` 记录，撤回时逐条（带记录 ID）撤回。
- `token-board/usage@1` `read`、`share`（本插件自己的协议，页面用）：`read` 读各台机器的用量、分享状态与镜像的好友记录；`share` 对这台的状态记录调 `set-share`，开关分享。
- `magpie/models@1` `read`（**可选**，写在 `optionalUses`）：读本机 Magpie 插件的同型号映射（只读的安全查询 `names`），见下面「型号与请求项」。没装 Magpie 插件、读不到或超时（10 秒）都当没有映射，行为与不映射完全相同。

没装或停用好友插件时，本机统计与 48 小时曲线照常运行、零报错，分享状态显示「未安装或未启用好友插件」（`no_gateway`）。

## 分享什么

向好友分享用量开启时，每 10 分钟经好友网关发布两种记录（默认发给你的好友），内容没变由网关按规范哈希去重、不重发：

- **月块日归档** `kind: coda/token-day`，`id: <sourceId>/<YYYY-MM>`，记录体 `{ v: 3, days: { "YYYY-MM-DD": { [agent]: [ { a, s, u, i, m, n } ] } } }`（一行的写法见下），按 UTC 日汇总，发布最近约 30 天所在的月份。一个月超过 60 KiB 时拆成 `<YYYY-MM>-1`（1–15 日）与 `-2`（16–31 日），再超按周 `-w1`…`-w5`，最后合并小型号。
- **48 小时滚动曲线** `kind: coda/token-today`，`id: <sourceId>`，记录体 `{ v: 3, slotMs, windowStart, windowEnd, slots: { "<槽起点毫秒>": { [agent]: [ { a, s, u, i, m, n } ] } } }`，默认 30 分钟一槽（超 60 KiB 降为 60 分钟一槽），每次覆盖同一条。
- **一行** `{ a, s, u, i, m, n }`：`a` 请求的模型 ID（`asked`），`s` 实际型号（`served`），`u` 同型号映射归并后的名字（可选，没有归并就不写，见下；不混进 `a` 或 `s`），`i` 模型服务的接口种类（如 `openai-responses`，**不带服务的 UUID**，别人机器上的资源 ID 好友用不上也不该拿到），`m` 未分层的旧标签（只在没有分层信息的行上，与 `a`、`s`、`u`、`i` 不同时出现），`n` 是 `[input, output, cacheRead, cacheWrite, turns, reportedTurns]`；没有的不写。后端允许只带服务的行，这样的行只有 `i`，型号名取服务的接口种类名。`a`、`s`、`u`、`m` 是身份：读写都原样保存、按字符串完全相等比较（不压缩空白），边界上只验类型与长度（1–200 字、不含 NUL），不合法的行整行丢弃；清洗只在页面显示时做。写记录时各行原样保留，包括只有回合数的请求行，不预先分配回合。
- **体积预算**：记录体不超过 60 KiB。放不下时按型号名（见下）逐级折叠：每个 Agent 只留 Token 最多的 32、8、2、1、0 个型号（并列取名字靠前的），其余各行并成一行 `m: "other"`；0 个也放不下就把每格所有 Agent 和型号合成 Agent `_` 下的一行 `m: "_"`，只留总量。折叠不改总量（含回合数），结果与输入顺序无关。
- **读取端**同时认旧版：`v: 2`（每个型号一个旧标签：`{ [agent]: { [model]: [6 个数] } }`）与更早的 `coda/token-usage`，旧记录按旧标签显示。
- `sourceId` 优先取 `coda/machine@1` 里本机的稳定机器 ID；读不到就沿用 `source.json` 里已有的（没有才生成一次随机 UUID），不会因为一时读不到换新 ID。从随机 UUID 换成机器 ID 后，旧 UUID 记在 `source.json` 的 `legacy`：榜单里不再把它名下的旧记录当成另一台机器，开启分享同步或撤回时也会逐条撤回它留下的旧记录。
- 不含机器名、会话、目录、正文和费用。0.1.0 发布的 `coda/token-usage`（`<UTC 日期>/<sourceId>`）只做过渡期兼容读取与撤回：某台机器只要有新版记录，就不再读它的旧版记录，不会双计。
- 关闭分享或点「撤回已发布的记录」，会先按本机 `sourceId`（及 `legacy` UUID）筛出自己的记录 ID，再逐条经网关撤回，好友不再看得到；**绝不按 kind 批量撤回**，同一作者其他设备的记录不会被误撤。撤回还会取消好友网关里排着的本机待发项（没有身份时也一样），免得恢复身份后把已撤回的用量发出去。没装好友插件时撤回不会假装成功，会保留本机已发 ID 的索引，装回后再撤；整轮没全部确认撤回（排了队、查询被截断、出错）时索引原样保留，等下次重试。同步里发布或必需的撤回只要有排队、暂停、需要证书、没身份或出错的，就不报「已同步」、不刷新上次同步时间。

统计和发布互不阻塞：没有好友插件、没有身份、没开分享、24 小时代签证书过期或好友插件暂停了这类数据的外发时，本机用量和当天曲线照常写进目录、照常显示。证书过期、暂停等由网关在本机排队，恢复后自动补发；同步状态如实写在这台的状态记录里（`disabled`、`no_gateway`、`no_identity`、`pending`、`needs_cert`、`paused`、`queued`、`synced` 或 `error`），页面只在证书过期和同步出错时另写一行。

## 型号与请求项

用量行的模型身份有三层：模型服务（`service`）、请求的模型（`asked`）、实际型号（`served`），旧数据只有一个未分层的标签（`model`）。榜单的分模型明细这样算：

- **型号名**（`lib/usage.mjs` 的 `modelName`，全插件只此一处）：`served`，没有取同型号映射归并后的名字 `same`（见下），再没有取 `asked`，再没有取旧标签 `model`。名字相同的行合成一行（旧标签行与分层行同名也合）。只带服务的行没有这几项，取服务的接口种类名。不建全局型号表，不猜实际型号，不回填旧数据。
- **同型号映射**：经 Magpie 走的请求拿不到实际型号（`served` 为空），请求的模型 ID 形如 `group/ds-flash`、`opencode-go/deepseek-v4.1-flash`。装了 Magpie 插件时，取数（重算本机用量记录、同步发布）开头向它读一次映射 `{ "<asked>": "<底层型号名>" }`（规则与怎样在 Magpie 里声明同型号见 Magpie 插件的 README；
  **手建组要所有成员的底层型号名都相同才归并**，否则它保持自己的名字单独一行），再套到本机行上：`asked` 命中、`served` 为空、行的 `service` **是本机 Magpie 插件提供的服务**（映射连同这些服务的资源引用一起返回）的，型号名取映射后的名字；有 `served` 的行、旧标签行，以及走别台或别的插件提供的服务的行都不套（A 机的 Agent 用 B 机的 Magpie 服务是常见用法，那些行的 `asked` 是 B 机 Magpie 里的名字）。
  展开型号行仍按原来的 `asked` 与接口种类列请求项，所以 `group/ds-flash`、`opencode-go/deepseek-v4.1-flash` 各是一项。
  映射属于提供模型服务的那台机器：**每台机器只对自己本机的行套自己的映射**，套出的名字写进它发布的记录（行里的 `u`，没有归并就不带），读取端读到就用它当型号名，不拿本机的映射去套别人记录里的行；同一空间里别的机器由那台的插件套好后经记录交回。
  没装 Magpie 插件、没有映射或读不到时，与不映射完全一样。
- **请求项**：型号行名下按（请求名，服务的接口种类）分开列出。请求名取 `asked`，没有取旧标签，再没有取 `served`（只有服务的行保持为空），所以历史上 Claude 官方直连的两种记法——只有 `served` 的行（带 Token）与只有 `asked` 的行（带回合，或恢复首轮的少量 Token）——是同一项，不会列出两条同名子项；不同别名（如 `opus`）或不同接口仍各是一项。
- **Agent**：型号行名下同时按 Agent 汇总四项 Token 与回合（`agents`），与型号行守恒；兜底占位符 `_` 在页面上不列。
- **回合**：轮数记在请求行（没有 `served` 的行）上，Token 可能在带 `served` 的行上。只在读取端的聚合（`Tally`）里分配一次，范围是当次查询窗口，本机与签名记录读回后走同一段聚合。同一请求项的请求行只有轮数没有 Token 时，轮数记到该请求项下 Token 最多的型号行（并列取名字靠前的）；请求项下没有带 Token 的型号行，就记到同一 Agent、同一接口下只有 `served`、且 `served` 等于这个 `asked` 的行（历史数据；绝不跨 Agent、跨接口，也不会把 Opus 的回合记给 Haiku）；都没有，就留在请求行。型号行的回合数是它名下请求项之和，同一轮只算一次；作者的总回合数是所有行相加，不受归并影响。

## 谁的用量

后端的用量按人（`person`，这台后端的根身份）分开记，同桶不同身份的行不相加。只有 `person` 是当前身份（好友网关给出的本机作者）或空字符串（没有身份的行）的本机行，才算作当前作者的用量：页面概览、榜单、当天曲线和经网关发布的记录都是这样，别的身份的行不计入也不发布。读不到身份（没装好友插件）时没有作者可归属，本机统计不按身份切、照常显示；有网关但还没有身份时，交给网关排队的记录只含无身份的行。

## 数据怎么流：目录记录

页面是**目录聚合视图**（清单 `contributes.directoryViews: ["board"]`，API Level 22），只读目录里本插件的协议 `token-board/usage@1` 的记录，不给模块发消息，也不逐台去读。各台的模块把数据写成记录，用 `coda.replace` 整份交出（内存里留着当前全集，每次只重算变了的那部分；启动时给一遍全集，记录是投影；内容没变宿主不重写）。一条记录的 `spec.record` 说它是哪一种：

- **`usage` 本机用量**：月块日归档的每一块（`coda/token-day`）和 48 小时曲线（`coda/token-today`），记录体就是发给好友的那份 v3（见下「分享什么」），另带作者（写它时的好友身份，没有身份为 `null`）、`sourceId` 与弃用的旧来源 ID `legacy`。只含当前作者与无身份的行（没装好友插件时没有作者可归属，不按身份切）。曲线约每分钟重算一次，只查最近 48 小时的桶；日归档跟着 10 分钟一次的同步重算。
- **`state` 这台的状态**：分享开没开、同步状态 `syncState`、上次同步成功的时刻、要人处理的同步错误（只在分享开着时写）、本机的好友身份，以及好友网关里的好友身份；关了分享后撤回没做完（网关不可用、撤回出错、排了队等代签证书续签）写在 `withdrawal` 里，分享关着也留着，定时同步会再撤一次，撤完才清。
- **`mirror` 镜像的签名记录**：好友和自己别的设备发布的 `coda/token-day`、`coda/token-today` 与旧版 `coda/token-usage`（`author`、`kind`、`id`、`version`、`body`）。本机自己发布的不镜像（本机用量记录就是它们的正本）。每 10 分钟同步时重算，好友网关（`friends/social@1`，模块用 `scope: 'local'` 订阅）有变化时也重算（去抖）；某个作者的某一种读失败，留着上一份。
  每条记录写进目录后不能超过 64 KiB（含持有方、ID 等外壳），`replace` 一条超限整份都写不进去，所以镜像来的记录按序列化大小留足余量，超限的跳过（本机的记录体已有 60 KiB 的预算）。

重启后模块先用 `coda.list` 把自己已有的记录读回内存全集再开始算：本机用量的曲线、日归档、好友镜像（与好友列表）哪一部分这一次读失败（用量查询抛错、读网关或好友抛错、网关回 `service_unavailable`），就留着它的上一份，只替换读成功的部分；只有确认没有好友网关（`not_found`、`forbidden`）才清掉镜像。

协议的操作只有 `set-share { on }`，由各台的模块实现：开就同步一次，关就撤回已发布的记录；页面对每台的状态记录各调一次。

## 看什么

页面（资源页里的「Token 消耗榜」），顶栏分段「今天 / 近 7 天 / 近 30 天」，每次打开都从「今天」开始；工具栏只有「分享」开关。页面等第一次 `watch` 给完现有的记录才画第一屏（之前不画数字，也没有「读取中」），之后只在记录变化时重画（合到一帧），展开状态保留；时间窗按看页面这台设备的当地时间算（`rangeWindow`）。

- **我 · 机器名**：视图里各台本机用量记录的合计（不分作者），总 Token 与回合数、输入／输出／缓存读／缓存写的四段条与图例、型号列表（先 5 个，「展开全部 N 个型号」）。每个型号行都能点开（右侧小箭头指示），看：回合数、占当前总 Token 的比例（小于 0.1% 写 `<0.1%`）、缓存命中率（缓存读 ÷ 输入、缓存读、缓存写之和，有缓存读才写）、该型号自己的四色条与四项数值，以及按 Agent 的拆分；不止一台机器用过这个型号时再按设备拆分（`merge.mjs` 按机器各算一遍再合，同一台的日归档与曲线不双计）；请求来源只在有区分价值时才列（多于一项、别名与型号名不同或带服务；同一型号既有服务接口又有直连的，无服务的标「直连」），只有一个与型号同名的官方直连项就不列。
- **好友榜**：每行排名、展示名、回合数、总量，「我」高亮并带标签，点开看分模型（同样可逐个展开，没有设备拆分）。没分享的好友不进排名，只写一行「还有 N 位好友没有分享」。没有好友（没装好友插件、没有 Accord 身份也一样）只写「还没有好友。加了好友、对方也开着分享，就能在这里比一比。」
- **页脚**一行灰字：「正在向好友分享 · HH:mm 已同步」或「没有分享，好友看不到你的用量」（撤回确认完成后才这样写）；只有要人处理的才另写一行：代签证书过期、同步出错（写哪台、什么错）、关了分享但撤回没完成（「已关闭分享，已发布的记录还没撤回完：<原因或等代签证书续签>」，出错的写明哪台）。
- **分享开关**：视图里各台的状态记录都开着才显示开；按下时对每台的状态记录调 `set-share`，某台没连上，页脚写「<机器名> 没连上，没有改」。在设置里改了分享开关，以设置为准。没装本插件、旧版或离线的机器：没有记录就不出现，离线的用目录里的最后一份。

### 好友榜怎么合

合并是纯函数（`lib/merge.mjs` 的 `summarize`），输入是目录里这些记录的条目与时间窗：

- 作者是各台状态记录里的本机作者，加上各台好友列表的并集；
- 每个（作者, `sourceId`）只算一次：有那台本机用量记录的，用本机的；否则在各台的镜像里取（作者, `kind`, `id`）版本最大的一条（好友撤回的空记录体版本最高就压过旧副本，也不算分享）；
- 同一作者下，`retired`（本机用量记录的 `legacy`）旧来源一律不要；某个来源有新版记录时，不读它的旧版 `coda/token-usage`；
- 时间窗的拼法（当天曲线与日归档、不双计）与排名（总 Token，平局按回合数、再按作者）在 `lib/usage.mjs` 的 `aggregateLeaderboard`。

用量按身份显示：展示名与好友页、好友对话一致：`昵称 #4 位十进制尾号`，如 `sakura #8283`。同昵称且末 4 位尾号相撞的公钥，按榜单里的全部作者一起从右往左逐位加位直到区分，如 `xs #04084`、`xs #14084`；合法但解不出昵称的公钥显示 8 位十六进制短码，如 `ffffffff`。昵称、尾号与撞号加位都由 WebView 标准库 `coda-view://lib/v1/accord.js`（即协议包 `@coda-console/protocol/accord`）计算，插件里没有自己的实现，也因此没有 npm 依赖。

## 设置

- `token-board.share`（默认开）：向好友分享用量。页面上的开关只在设置没再改动之前有效；在设置里改了，以设置为准。
