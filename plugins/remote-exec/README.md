# 远程执行

让空间里别的机器上的 Agent 在这台机器上执行命令、拉取和推送文件。适合这种场景：Mac 上的 Agent 要操作空间里的安卓机，而那台机器上只装了 Coda 后端、没有 Agent。

**默认关闭。** 在「设置 › 插件 › 远程执行」打开「允许本空间的机器在这台上执行」才生效；开关属于机器，关闭后这台不再出现在可用机器里，对它的操作会被明确拒绝（`disabled`）。

> **打开它，等于让空间里的机器以这台后端所在的系统用户的身份做任何事**：执行任意命令、读写这个用户能碰的所有文件，相当于 SSH 登录这个账号。默认不限制，也没有白名单或需要你批准的环节；区别于 SSH 的只是每次操作都有记录。调用方可以在执行时带 `restrict` 把这一次收紧到几个目录里（只支持 macOS，见[受限执行](#受限执行restrict)），但不带就是不受限，拉取与推送也始终不受限。只在你信任空间里每一台机器（和它上面的 Agent）时打开。

## 怎么装

**两侧都要装。** 目标机装它，是为了真的能被操作；调用机装它，只是为了让后端认识这个协议，调用机一侧没有这个插件的代码在运行。调用机上不需要打开开关。

**会话工具依赖后端支持**：要调用机上的会话把这三样列成工具，需要支持「会话调用插件的操作与流」的 Coda 后端版本（coda#2981）；后端还不支持时，协议与记录照样在，只是会话里没有这三个工具。支持之后，工具里的 `target` 写目标机的机器名（也认 `coda://` 地址）；当前可用的机器及其系统、用户、默认目录，开会话时会列给 Agent，也能随时用 `coda resources list` 看。

## 三个工具

- **执行（`exec`）**：在目标机上用 `/bin/sh -c` 执行一条命令，以后端所在用户的权限运行，等它结束后返回退出码、stdout 和 stderr。
  - `cwd`（目标机上的绝对路径）不给就在机器的默认目录（这个用户的主目录）运行；`stdin` 给了就一次写入后关闭，不给就是空输入。
  - `restrict`（可选）：只让这次命令在列出的几个目录里读写，见[受限执行](#受限执行restrict)；不给行为和以前完全一致。
  - **时限**：`timeout` 以秒计，默认 120，最长 600。超时会结束整个进程组，返回 `timedOut: true` 和已有的输出。Agent 取消调用时同样结束整个进程组。命令里起的脱离进程组的进程（新会话）不在其内，若它仍拿着继承来的输出管道，结束后最多再等约 2 秒就放弃收输出、照常返回。
  - **截短**：stdout 与 stderr 各最多保留约 24 KiB（开头和结尾各一半，中间注明省略了多少字节），超出时 `truncated` 为 `true`。完整输出在目标机上这个插件的状态目录里（`<状态根>/plugins/remote-exec/outputs/` 的真实路径下，只有本人可进，每个后端实例各有一份），`outputDir` 是它的路径（里面是 `stdout`、`stderr` 两个文件），用拉取取回；没有截短时不留任何文件。
  - **落盘上限与回收**：每路输出落盘至多 16 MiB，再多的不写（只继续数字节、留尾），这时截短说明里写明「落盘也截断了」和实际存了多少。留下的输出目录在三个时候回收：一次执行决定留下输出的那一刻（把它算进总量）、插件启动时、之后每小时一次。回收时超过 24 小时的删掉；所有留下的合计超过 256 MiB 时，从最旧的删起；正在写的不删。所以一份输出最多留约 25 小时，合计超过 256 MiB 的部分在留下新输出时当场删掉。回收只在这个插件实例自己的输出目录里做，不碰系统临时目录或别的后端实例的。
  - **同时在跑**：一台机器同时至多 8 个执行，再来的以 `too_many_running` 拒绝（什么都没做，`effects: none`）。
  - 被信号结束的命令 `exitCode` 为 `null`，`signal` 是信号名。
  - 请求和回答各自编码后都不能超过 1 MiB，大的内容用拉取、推送传。
  - 需要长时间运行的任务，放到后台再回来查。
  - **环境不继承后端**：命令从干净的环境起，只带这几项（参照非交互的远程登录）：`PATH`、`HOME`、`USER`、`LOGNAME`、`SHELL`、`LANG`、所有 `LC_*`、`TMPDIR`、`TZ`；后端的值照抄，`HOME`、`USER`、`LOGNAME`、`SHELL` 缺了按后端所在的系统用户补，`PATH` 缺了用 `/usr/local/bin:/usr/bin:/bin`。任何 `CODA_` 开头的都不带，后端环境里的别的变量（云凭据、包仓库令牌等）一概不带。
- **拉取（`pull`）**：读目标机上的一个文件（绝对路径），可以用 `offset`、`length` 按字节范围读，不给就读全部。文件落到本会话的临时目录，工具返回本地路径。只读普通文件（非阻塞地打开、再按打开的对象判断，没有写端的 FIFO 也不会挂住）：文件不存在、是目录（`is_a_directory`）、FIFO／设备／套接字（`not_a_regular_file`）、没有权限都是带码的明确错误。`stat` 报大小为 0 的文件（如 `/proc` 下的）读到结尾为止，这时回答里没有 `content-length`，操作记录里的字节数是实际送出的。
- **推送（`push`）**：把本地的一个文件整份写到目标机的 `path`（绝对路径），至多 1 GiB，超出的以 `too_large` 拒绝（临时文件删掉，原文件不动）。已有的同名文件被替换（沿用原文件的权限位，不保留特殊权限位（setuid、setgid、sticky），属于别的用户的文件不替换（`owner_mismatch`），属组改不成也拒绝；是符号链接就写到它指向的文件、保留链接；链接悬空就写到它指向的路径（链接指向的目录不存在时拒绝，`not_found`），链接绕成圈报 `symlink_loop`；已有的目标是目录（`is_a_directory`）或 FIFO／设备／套接字（`not_a_regular_file`）则拒绝），父目录不存在先建（逐级新建；失败或中止时临时文件和本次新建的目录各自收回，有任何收不掉的，`effects` 是 `unknown`）。先写同目录里的临时文件、写完再改名，所以中途失败或中止时原文件不变；重复推送结果相同。回答是写入的路径与字节数。

要改目标机上的文件：拉到本地，用原生工具改，再推回去。不单设读文件、列目录的工具，用执行跑 `cat`、`ls`。

## 操作记录

每次操作（执行、拉取、推送，包括被拒绝的）在目标机的插件状态目录（`<状态根>/plugins/remote-exec/`）里的 `audit.jsonl` 追加**两行** JSON：**动手之前**一行「开始」，结束之后一行结果，两行用同一个 `op` 关联。文件建成 `0600`（已有的更宽也收成 `0600`）；它是符号链接、目录、FIFO 或别的不是普通文件的东西时不写。**不轮转**，也没有查看界面，需要时自己读这个文件。

「开始」（`phase: "start"`）的字段：

| 字段 | 内容 |
| --- | --- |
| `time` | 记录的时间（ISO 8601） |
| `op` | 这次操作的编号，结果那一行用同一个 |
| `id` | 调用号（只有执行有；拉取、推送没有） |
| `caller` | 谁发起的，原样存下。`machine` 是这台机器自己核验过的调用方机器；`plugin`、`parent`（发起的会话等）是来源后端转述的，这台无法独立核验；以后可能还有别的字段 |
| `operation` | `exec`、`pull`、`push` |
| `params` | 执行是命令全文、目录与传入的 `timeout`（没给就没有这一项，不记 `stdin`），带了 `restrict` 的还有 `restrict`（原样的 `{ dirs: [{ path, access }] }`，含 rw／ro 标记；没带就没有这一项），受限且没给 cwd 时 `cwd` 记的是第一条 rw 目录；拉取是路径与范围；推送是路径 |

结果（`phase: "end"`）的字段：`time`、`op`、`operation`，加上 `result`（执行是 `exitCode`、`signal`、`timedOut`；拉取、推送是 `bytes`）或 `error`（被拒绝或失败的错误码，如 `disabled`、`not_found`、`cancelled`、`timeout`、`too_large`、`too_many_running`，受限执行被拒绝的见下面的错误码表），以及 `ms`（耗时，毫秒）。

拉取在内容送完（或中途断开）之后、回答结束之前补结果那一行。

**先记后做**：「开始」写不进去（没有状态目录、建不出来、记录文件不是普通文件或打不开）时，这次操作以 `audit_unavailable` 拒绝、什么也没做（`effects: none`）；顺序是开关、判定点、记「开始」、执行、记结果（开关或判定点拒绝的也记两行）。操作已经做完、补结果那一行才失败（如磁盘满）的，**不改变已完成操作的结局**（调用方据此可能重做），只在这台后端的标准错误写明是哪次调用（操作编号、调用号、路径）的结果丢了；这时记录里只有「开始」没有结果。

## 受限执行（`restrict`）

`exec` 可选的 `restrict` 参数：`{ dirs: [{ path, access: "rw" | "ro" }] }`，`path` 是目标机上的绝对路径，`access` 是 `rw`（可读写）或 `ro`（只读）。至少一行、至多 50 行，至少一行是 `rw`。带了它，命令经 macOS 的 `/usr/bin/sandbox-exec` 起，只有这些目录（连同它们下面的一切）里的文件内容读得到、写得到（`ro` 只读），再加系统自带的只读部分（见下）和本次调用专用的临时目录。**这个参数只会收紧权限，所以任何调用方都可以带，这台不需要认识调用方是谁。**

**先看这台支不支持**，两层：(a) 提示：记录的 `os` 以 `Darwin` 开头才可能支持（只有 macOS 支持；记录的形状没有为此加字段，因为空间里还没升级的机器按旧的 `status`、`spec` 定义接收镜像，多出的键会让整条记录被丢掉）；(b) 权威：发一次带 `restrict` 的 `exec` 探测——返回 `sandbox_unsupported`（这台是 macOS 以外的系统、或没有可执行的 `/usr/bin/sandbox-exec`），或旧版目标机按 schema 拒绝 `restrict` 这个字段（`invalid_input`），都表示不支持。不支持时都是被拒绝、什么也没做，**绝不退回不受限执行**。

### 挡住什么

- 允许目录之外的文件内容读写：家目录里没列出的一切、`~/.ssh`、Coda 的状态根（含本插件的状态目录——`audit.jsonl`、`outputs/`——和同一状态根下别的插件的状态目录）、别的目录、别的受限调用的临时目录。
- 子进程、孙进程一样受限（沙箱由进程继承，`sh -c 'sh -c "cat …"'`、`xargs`、后台任务都一样被拒；测试里实测）。
- 允许目录里的符号链接指到目录外，一样读写不到（按真实路径判定）。
- 路径一律先解析成真实路径再写进 profile（`/tmp` 是 `/private/tmp`，`$TMPDIR` 在 `/private/var/folders` 下……），路径不拼进 profile 文本，而是以 `sandbox-exec -D 名=值` 传、profile 里用 `(param "名")` 引用，所以含引号、反斜杠、括号、换行的路径不会造成 profile 注入（不转义也不拒绝，原样用；测试里用这样的目录名实跑）。
- 允许目录若包含或落在受保护的位置里（Coda 的状态根、家目录的 `~/.ssh`；所以授出 `~`、`/`、状态根、状态根里的任何目录都不行），以 `restrict_protected` 拒绝。
- 允许目录之间不能重叠，否则以 `restrict_overlap` 拒绝（消息里写出冲突的两条，用调用方给的原写法）：字面上相同或一条在另一条里面（规范掉 `.`、多余斜杠、结尾斜杠后；经符号链接、不同大小写的拼写到达的也认），或真实路径相同、一条在另一条里面。原因：目标机每次调用都重新解析路径，若一条路径字面上经过另一条 `rw` 目录的内部，受限命令能把其中的目录换成指向别处的链接，下一次调用就会放行机主没核对过的目录；`rw` 目录里的 `ro` 子目录与重复的目录，profile 里实际是可写的，不能让授权显示成只读。
- `cwd`：给了就必须（按真实路径）落在某条允许目录内，否则 `cwd_not_allowed`；不给用**第一条 `rw` 目录**（不是家目录）。
- 临时目录：每次调用在状态目录的 `sandbox-tmp/` 下新建一个（`0700`），`TMPDIR` 指向它，命令结束后删除（成功、失败、超时、取消、起进程失败都删；后端崩了留下的，下次启动时清）。命令把里面的子目录改成 `chmod 000` 之类删不掉的，清理会先递归恢复权限（只对目录动手，不跟随符号链接）再删；仍然删不掉也不改变这次调用的结局（退出码、输出、操作记录的结果行照旧），原因只写后端标准错误，残留的目录改名成 `dead-` 开头、不会再被任何调用用到，由每小时一次的定期回收（与输出的回收同一个）删掉。它在状态根里，别的受限调用（它们不能授出状态根）够不着。读 `TMPDIR` 的程序都能用；不看 `TMPDIR` 的（不带模板的 `mktemp`、`mktemp -t`、按系统用户临时目录 `/var/folders/…` 写的程序）在沙箱里写不了，调用方要自己用 `"$TMPDIR/x.XXXXXX"` 这样指路。
- 同样是系统用户，同一台上不受限的调用（以及后端自己）仍够得着这些东西，受限只约束带了 `restrict` 的那条命令。

### 挡不住什么（`system.sb` 的例外）

profile 以系统自带的 `/System/Library/Sandbox/Profiles/system.sb` 为底（自写的更窄的 profile 在两台 Mac 上会让进程 SIGABRT）。下面按 macOS 27.2.1（构建 26B131）上这个文件的实际内容核对；**系统规则可能随 macOS 版本变化**，换了版本需要重新核对。它自带、也就一并带进来的例外里，对「目录外的东西能被看到」有影响的是：

- **文件**：下面这些在允许目录之外也读得到（内容或存在性）：`/System`、`/usr/lib`、`/usr/share`、`/Library/Apple`、`/Library/Filesystems/NetFSPlugins`、`/Library/Preferences/Logging`、`/private/var/db/timezone`、`/private/var/db/DarwinDirectory/local/recordStore.data`、`/private/var/db/eligibilityd/eligibility.plist`、`/private/etc/passwd`、`/private/etc/master.passwd`、`/private/etc/services`、`/private/etc/protocols`、`/dev/random`、`/dev/urandom`、`/dev/autofs_nowait`、`/dev/dtracehelper` 等若干系统数据文件与标准设备；`/` 本身（能列出根目录的名字）；`/etc`、`/tmp`、`/var` 这几个链接的存在性。再加本插件为让命令跑得起来额外放行只读的 `/usr`（含 `/usr/local`）、`/bin`、`/sbin`、`/private/etc`、`/private/var/select`，其中的东西（例如 `/usr/local` 里装的东西、`/etc` 里的配置）命令都读得到，也可以执行。
- **Mach／XPC**：`system.sb` 放行了一批系统 Mach 服务的查找（用户与组信息 opendirectoryd、cfprefsd、logd、trustd、runningboard 等），并在 SBPL 版本兼容时放行**任何** XPC 服务名的查找，还放行 `mach-register`、`sysctl-read`（全部系统参数可读）。这些服务以它们自己的权限运行，不受这份 profile 约束：理论上能通过它们间接读到目录外的东西。这个通道没有在本插件里封，也没有逐个测过；要防这个，不要把需要保密的东西放在能被某个系统服务代读的地方。
- **网络**：本插件不设网络规则，也不承诺禁网。`system.sb` 放行了到系统日志 Unix 套接字 `/private/var/run/syslog` 的出站连接（`network-outbound`），并放行了几个共享内存的读取（`apple.shm.notification_center`、`apple.cfprefs.*`）；它还定义了 `(system-network)`（放行网络的一组规则）但自己没有调用，本插件也不调用。所以在这个版本上、deny-default 的 profile 下，实测对外 TCP 连接失败（`nc` 到 1.1.1.1:443、`curl` 都连不上），但这是系统文件内容的结果，不是承诺；本机回环与其他 Unix 套接字没有测过，也不要依赖。

### 启动链

`ctx.spawn` 起的第一个进程仍是 `/usr/bin/env`，和不受限时一样，只有它拿到后端注入的环境与插件令牌：

```
/usr/bin/env -i <白名单环境，TMPDIR 换成本次的临时目录> /usr/bin/sandbox-exec -D D0=… -D TMP=… -p <profile> /bin/sh -c <命令>
```

`env` 清空环境后 exec 成 `sandbox-exec`，`sandbox-exec` 加载 profile 后 exec 成 `sh`；三者是同一个进程（pid、进程组不变，取消与超时照旧结束整个进程组）。所以 `sandbox-exec` 与用户命令拿到的都是清过的环境（白名单同上，没有 `CODA_` 开头的变量、没有插件令牌），不比不受限时暴露得更多。

**起真命令前先空跑一次**：同一份 profile、同一条启动链，只是命令换成 `:`。`sandbox-exec` 自己的失败（profile 不合是退出码 65，`sandbox_apply` 或 exec 不了 `/bin/sh` 是 71）与用户命令自己的退出码在数字上分不开，命令完全可能自己 `exit 71`，所以不靠真命令的退出码去猜；空跑不过就以 `sandbox_failed` 拒绝，真命令不起；空跑过了，真命令的任何退出码都是命令自己的普通结果。多一次几毫秒的进程换来的是这个分界不会被命令伪造或搞混。

**一种少见的例外**：空跑通过之后、正式启动时沙箱又加载失败（极少见的竞态，如系统刚好在这两次之间变了），用户命令不会执行、也不会越权，但结果会表现为 `sandbox-exec` 自己的退出码（71）加它写在 `stderr` 里的原话，而不是 `sandbox_failed`；归类不准，没有为它另加握手通道。

### 错误码

被拒绝的一律 `effects: none`，在起任何用户命令之前，操作记录里是「开始」加带码的「结果」两行：

| 码 | 什么时候 |
| --- | --- |
| `disabled`、`audit_unavailable`、`too_many_running` | 和不受限的执行一样 |
| `invalid_input` | `restrict` 的形状不对（不是 `{ dirs }`、`dirs` 不是 1 到 50 项、项不是 `{ path, access }`、`path` 不是绝对路径、`access` 不是 `rw`／`ro`、没有 `rw`），或 `cwd` 不是绝对路径 |
| `sandbox_unsupported` | 这台不是 macOS，或没有可执行的 `/usr/bin/sandbox-exec` |
| `restrict_dir_not_found` | 某条允许目录不存在 |
| `restrict_dir_not_a_directory` | 某条允许目录不是目录 |
| `restrict_protected` | 某条允许目录包含或落在受保护位置里（Coda 状态根、`~/.ssh`） |
| `restrict_overlap` | 允许目录互相重叠：字面上相同或一条在另一条里面，或真实路径相同、一条在另一条里面（消息里写出冲突的两条） |
| `cwd_not_allowed` | `cwd` 的真实路径不在任何一条允许目录里 |
| `not_found`、`not_a_directory` | `cwd` 不存在、不是目录（同不受限的执行） |
| `sandbox_failed` | 这次调用的临时目录建不出，或空跑不过（沙箱起不来；消息里有 `sandbox-exec` 的原话） |

### 截短输出与 `outputDir`

受限调用的完整输出照旧由插件进程（在沙箱之外）写进状态目录的 `outputs/`，结果里的 `outputDir` 照旧回这个路径，截短说明里也照旧写着路径。**受限的命令自己读不到它**（状态根整个在沙箱外，实测），所以要拿完整输出：由机主，或不带 `restrict`、有权限的调用（如拉取 `outputDir` 里的 `stdout`、`stderr`）去取；拉取不受 `restrict` 约束，受限的那条命令也不是拉取的发起方。这样做的好处是受限与不受限的调用结果一个形状、回收规则一致（每路至多 16 MiB、至多 24 小时），不为受限调用另开一套；代价是返回的路径会让调用方看到状态根在哪（路径名本来就在截短说明里）。

## 已知限制与第一版不做的

- 放开程度与 SSH 登录该账号相当。区别在于看得见，以及调用方可以在执行时带 `restrict` 收紧这一次（见上）。
- 这台核验得到的调用方是机器；会话是调用机的 Coda 转述的，Agent 伪造不了，但这台无法独立核验。
- 现有的批准卡都开在发起方的会话里，没有现成的路能把问题问到这台机器的机主。
- 长任务由 Agent 在远端放后台再回来查。命令结束时，它留在后台的进程会随进程组一起被后端收掉（`&`、`nohup` 都留不住），要常驻的任务用目标机自己的服务管理起。
- 子进程另起会话并脱离父进程后（如 `setsid`），取消与超时收不掉它：结束的只是命令自己的进程组。
- 关掉开关不会中止已经在跑的操作，只拒绝之后来的。
- 不受限的命令和后端是同一个系统用户，改得了操作记录。操作记录防得住误操作，防不住有意抹掉痕迹的不受限调用方；带了 `restrict` 的命令读写不到状态目录，改不了它。
- 起进程时，启动链上的第一个进程（`/usr/bin/env`）仍会拿到后端注入的环境与插件令牌，它随即清空环境，传给 shell 的才是清过的：这是后端起进程（`ctx.spawn`）的行为，要改得动后端。受限执行在 `env` 与 `sh` 之间多一层 `sandbox-exec`，它拿到的已经是清过的环境（见上面的启动链）。
- 推送是先写临时文件再改名替换，不保留原文件的扩展属性、资源叉与访问控制列表。
- 报告的大小比实际内容长的虚拟文件（如 Linux sysfs 的一些属性）拉取时报 `short_read`，用执行跑 `cat` 读。
- 安卓机上执行看到的是 chroot 里的 Debian，要碰安卓本体由 Agent 在命令里自己写 `nsenter`。
- **受限执行的限制**：
  - 只支持 macOS；Linux、安卓上带 `restrict` 的调用以 `sandbox_unsupported` 拒绝。
  - 只限制文件内容的读写：不禁网、不限 CPU／内存／进程数；目录是否存在、元信息（`stat`、列目录的名字）不保证不可见，`system.sb` 放行的东西见上。
  - `setsid` 脱离进程组的后代进程仍收不掉（同不受限的执行），命令结束后它们仍带着沙箱，但会留在后台，也可能还拿着已经删掉的临时目录。
  - `sandbox-exec` 已被系统标为弃用，目前可用；系统更新后行为可能变，空跑探测会把「起不来」报成 `sandbox_failed`，不会悄悄不受限。
  - Xcode、Homebrew 等工具链在沙箱里不保证能跑（`/opt/homebrew`、`/Applications`、`xcode-select` 的开发者目录默认不放行，需要的话把它们作为允许目录授出，但这样它们里的东西就都读得到了）；`ps` 之类带 setuid 的系统命令也起不来。
- 不做：交互式终端、边读边写的输入、白名单、Linux／安卓上的沙箱、禁网与资源上限、操作记录的查看界面、命令行入口、Windows（后端本身还不支持）。本插件不认识调用方是谁：谁来调用都按同一套规则，要对谁收紧由调用方在每次调用里带 `restrict`。
