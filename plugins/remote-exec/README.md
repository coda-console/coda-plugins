# 远程执行

让空间里别的机器上的 Agent 在这台机器上执行命令、拉取和推送文件。适合这种场景：Mac 上的 Agent 要操作空间里的安卓机，而那台机器上只装了 Coda 后端、没有 Agent。

**默认关闭。** 在「设置 › 插件 › 远程执行」打开「允许本空间的机器在这台上执行」才生效；开关属于机器，关闭后这台不再出现在可用机器里，对它的操作会被明确拒绝（`disabled`）。

> **打开它，等于让空间里的机器以这台后端所在的系统用户的身份做任何事**：执行任意命令、读写这个用户能碰的所有文件，相当于 SSH 登录这个账号。第一版不限制，也没有白名单、沙箱或需要你批准的环节；区别于 SSH 的只是每次操作都有记录。只在你信任空间里每一台机器（和它上面的 Agent）时打开。

## 怎么装

**两侧都要装。** 目标机装它，是为了真的能被操作；调用机装它，只是为了让后端认识这个协议，调用机一侧没有这个插件的代码在运行。调用机上不需要打开开关。

调用机上的会话会得到三个工具，工具里的 `target` 写目标机的机器名（也认 `coda://` 地址）。当前可用的机器及其系统、用户、默认目录，开会话时会列给 Agent，也能随时用 `coda resources list` 看。

## 三个工具

- **执行（`exec`）**：在目标机上用 `/bin/sh -c` 执行一条命令，以后端所在用户的权限运行，等它结束后返回退出码、stdout 和 stderr。
  - `cwd`（目标机上的绝对路径）不给就在机器的默认目录（这个用户的主目录）运行；`stdin` 给了就一次写入后关闭，不给就是空输入。
  - **时限**：`timeout` 以秒计，默认 120，最长 600。超时会结束整个进程组，返回 `timedOut: true` 和已有的输出。Agent 取消调用时同样结束整个进程组。命令里起的脱离进程组的进程（新会话）不在其内，若它仍拿着继承来的输出管道，结束后最多再等约 2 秒就放弃收输出、照常返回。
  - **截短**：stdout 与 stderr 各最多保留约 24 KiB（开头和结尾各一半，中间注明省略了多少字节），超出时 `truncated` 为 `true`。完整输出在目标机的系统临时目录里，`outputDir` 是它的路径（里面是 `stdout`、`stderr` 两个文件），用拉取取回。**这个目录不会自动清理**，不需要时自己删；没有截短时不留任何文件。
  - 被信号结束的命令 `exitCode` 为 `null`，`signal` 是信号名。
  - 请求和回答各自编码后都不能超过 1 MiB，大的内容用拉取、推送传。
  - 需要长时间运行的任务，放到后台再回来查。
  - 执行进程看不到插件自己的令牌（`CODA_TOKEN`）。
- **拉取（`pull`）**：读目标机上的一个文件（绝对路径），可以用 `offset`、`length` 按字节范围读，不给就读全部。文件落到本会话的临时目录，工具返回本地路径。只读普通文件：文件不存在、是目录（`is_a_directory`）、FIFO／设备／套接字（`not_a_regular_file`）、没有权限都是带码的明确错误。`stat` 报大小为 0 的文件（如 `/proc` 下的）读到结尾为止，这时回答里没有 `content-length`，操作记录里的字节数是实际送出的。
- **推送（`push`）**：把本地的一个文件整份写到目标机的 `path`（绝对路径）。已有的同名文件被替换（沿用原文件的权限位；是符号链接就写到它指向的文件、保留链接；链接悬空就写到它指向的路径（链接指向的目录不存在时拒绝，`not_found`），链接绕成圈报 `symlink_loop`；已有的目标是目录（`is_a_directory`）或 FIFO／设备／套接字（`not_a_regular_file`）则拒绝），父目录不存在先建（逐级新建；失败或中止时临时文件和本次新建的目录各自收回，有任何收不掉的，`effects` 是 `unknown`）。先写同目录里的临时文件、写完再改名，所以中途失败或中止时原文件不变；重复推送结果相同。回答是写入的路径与字节数。

要改目标机上的文件：拉到本地，用原生工具改，再推回去。不单设读文件、列目录的工具，用执行跑 `cat`、`ls`。

## 操作记录

每次操作（执行、拉取、推送，包括被拒绝的）在目标机的插件状态目录（`<状态根>/plugins/remote-exec/`）里追加一行 JSON 到 `audit.jsonl`。**不轮转**，也没有查看界面，需要时自己读这个文件。

每行的字段：

| 字段 | 内容 |
| --- | --- |
| `time` | 记录的时间（ISO 8601） |
| `id` | 调用号（只有执行有；拉取、推送没有） |
| `caller` | 谁发起的，原样存下。`machine` 是这台机器自己核验过的调用方机器；`plugin`、`parent`（发起的会话等）是来源后端转述的，这台无法独立核验；以后可能还有别的字段 |
| `operation` | `exec`、`pull`、`push` |
| `params` | 执行是命令全文、目录与传入的 `timeout`（没给就没有这一项，不记 `stdin`）；拉取是路径与范围；推送是路径 |
| `result` | 执行是 `exitCode`、`signal`、`timedOut`；拉取、推送是 `bytes`。被拒绝或失败的没有这个字段 |
| `error` | 被拒绝或失败的错误码（如 `disabled`、`not_found`、`cancelled`、`timeout`） |
| `ms` | 耗时（毫秒） |

拉取是在内容送完（或中途断开）之后才记那一行。

**每次操作都要有记录**：开始之前记录就写不了（没有状态目录、建不出来、记录文件打不开）时，这次操作以 `audit_unavailable` 拒绝、什么也没做（`effects: none`）；顺序是开关、判定点、记录可写、执行。操作已经做完、追加那一行才失败（如磁盘满）的，**不改变已完成操作的结局**（调用方据此可能重做），只在这台后端的标准错误写明是哪次调用（调用号、操作、路径）的记录丢了。

## 已知限制与第一版不做的

- 放开程度与 SSH 登录该账号相当。区别在于看得见、以后能收紧。
- 这台核验得到的调用方是机器；会话是调用机的 Coda 转述的，Agent 伪造不了，但这台无法独立核验。
- 现有的批准卡都开在发起方的会话里，没有现成的路能把问题问到这台机器的机主。
- 长任务由 Agent 在远端放后台再回来查。命令结束时，它留在后台的进程会随进程组一起被后端收掉（`&`、`nohup` 都留不住），要常驻的任务用目标机自己的服务管理起。
- 安卓机上执行看到的是 chroot 里的 Debian，要碰安卓本体由 Agent 在命令里自己写 `nsenter`。
- 不做：交互式终端、边读边写的输入、白名单与沙箱、对好友开放、操作记录的查看界面、命令行入口、Windows（后端本身还不支持）。
